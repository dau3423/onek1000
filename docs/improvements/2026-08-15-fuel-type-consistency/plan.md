# 기획서: 유종(연료 종류) 전면 반영 — 검색·상세·셀프 필터 일관성

- 작성일: 2026-08-15 (product-planner)
- 입력: `docs/improvements/2026-08-15-fuel-type-consistency/research.md`, `docs/요구사항_명세서.md`(SRS FR-1.3 / FR-3.4 / FR-4.1)
- 후속: 화면 변경(검색 결과 행, 상세 추이 탭, 필터 칩)이 있으므로 이후 사이클 단계에서 **ux-designer가 시각 디테일을 확정**한다. 본 기획서는 행위(AC) 기준을 고정한다.

## 배경·목표

지도(홈)는 유종을 완전 지원한다 — 유종 상태(`stores/map.ts`의 `product`), 칩 UI, 유종별 bbox/TOP10 재조회, 경쟁 방어까지 갖췄고, 차량 기본 유종 자동 선택(`initProductFromVehicle`)으로 "내 차 연료 기준 표시"라는 업계 표준 UX(티맵/카카오내비)를 따른다. 그런데 **검색과 상세로 넘어가는 순간 휘발유(B027)로 되돌아간다**:

1. **검색이 휘발유 전용**(`app/api/search/route.ts:34~36`): product 파라미터 자체가 없고, `prices_latest!inner` + `eq(product,'B027')` 조합 때문에 **B027 가격 행이 없는 주유소(LPG 전용 충전소 등)는 이름으로 검색해도 "검색 결과 없음"이 되는 결함**이 있다. 충전소가 희소한 LPG 사용자에게 이름/지역 검색의 가치가 가장 큰데, 정확히 그 세그먼트에서 업소가 통째로 누락된다.
2. **상세의 30일 추이·주유기록 단가가 휘발유 고정**(`app/station/[id]/page.tsx:110~113`, `:134`): LPG 차주가 충전소 상세에서 보는 차트가 자기 연료가 아니고, 주유기록의 리터↔금액 추정 단가도 휘발유 기준이라 계산이 틀어진다.
3. **셀프 필터 부재**: SRS FR-1.3에 명시된 기능("유종 + 브랜드 + **셀프** 필터")이 미구현. 셀프는 통상 더 저렴해 "최저가 찾기" 코어 가치와 직결되며, 데이터(`isSelf`)는 이미 bbox/radius/회색 점 응답에 전부 실려 온다 — 순수 UI/스토어 작업만 남았다.

**대상 세그먼트**: 경유·LPG 차량은 국내 등록차의 약 44% 수준(경유 화물/영업용 + LPG 택시·렌터카 중심)으로, 본 서비스 타깃(기름값에 민감한 출퇴근·장거리·영업·물류 운전자, 라이더)과 정확히 겹친다. 이들에게 서비스가 현재 "반쪽"으로 동작한다.

**이번 사이클이 끝나면**: 경유/LPG 사용자가 지도에서 고른 유종이 검색 결과 가격 → 상세 추이 차트 → 주유기록 단가까지 끊김 없이 이어지고, 셀프 주유소만 골라 볼 수 있게 된다.

> 프레이밍: 신규 기능 추가가 아니라 **일관성 결함(regression급 UX 버그) 해소 + SRS FR-1.3 정합**이다. research.md에서 발견된 하위 이슈 2건 — (a) 검색 inner join으로 인한 비휘발유 전용 업소 검색 누락 버그, (b) 주유기록 단가 B027 고정 — 은 별도 FR로 분리하지 않고 각각 **FR-1, FR-2에 흡수**했다.

## 유저 스토리

- **경유 차주(장거리/물류)로서**, 지도에서 경유를 선택한 상태 그대로 주유소 이름을 검색하고 싶다. 그래서 검색 결과에서 휘발유가 아닌 **경유 가격**으로 비교하고 바로 들어갈 수 있다.
- **LPG 라이더/택시 기사로서**, 희소한 충전소를 이름·지역으로 검색해 찾고 싶다. 그래서 지금처럼 LPG 전용 충전소가 "검색 결과 없음"으로 나오는 일 없이, **충전소가 반드시 검색에 노출**되고 LPG 가격을 확인할 수 있다.
- **LPG 차주로서**, 충전소 상세에서 **내 연료의 30일 가격 추이**를 보고 싶다. 그래서 지금 넣는 게 유리한지 판단할 수 있다.
- **경유 차주로서**, 주유기록을 남길 때 리터↔금액 추정이 **경유 단가** 기준이면 좋겠다. 그래서 연비 계산이 틀어지지 않는다.
- **셀프 선호 저가 탐색자로서**, 지도에서 **셀프 주유소만** 걸러 보고 싶다. 그래서 같은 화면에서 더 싼 선택지를 빠르게 좁힐 수 있다.

## 기능 요구사항

### FR-1: 검색 유종 반영 (+ 비휘발유 전용 업소 검색 누락 버그 수정)

- **설명**:
  - `/api/search`에 `product` 쿼리 파라미터를 추가한다. 값은 `PRODUCT_LABEL` 키 화이트리스트로 검증(미지정 시 `'B027'` 기본 — history API와 동일 관례, 화이트리스트 밖 값은 400 — SRS §5 공통 규약).
  - Mock 분기도 `getMockStations(product)`로 유종을 반영한다(SRS §9 Mock 우선).
  - **inner join 제거(left join화)**: `prices_latest!inner(product, price)` → `prices_latest(product, price)`로 바꾸고 `.eq('prices_latest.product', product)`는 임베드 필터로 유지한다. 해당 유종 가격이 없는 업소도 항상 검색되며 `price: null`로 응답한다(응답 `product` 필드는 요청 유종을 반영). 이름 검색의 1차 목적은 "업소 발견"이므로 left join이 정합 — research §4 FR-1 권장안 채택. 구현 시 실 Supabase에서 "부모 행 유지 + 임베드만 필터" 동작을 1회 검증하고, 불일치 시 2쿼리 대안(stations 검색 → `prices_latest.in(station_ids)+eq(product)`)으로 전환한다(리스크 §미해결-2).
  - `app/search/page.tsx`: `useMapStore()`의 `product`를 읽어 `&product=`로 전달한다. `Result` 인터페이스에 `product`를 추가하고, 결과 행에 **유종 라벨(`PRODUCT_LABEL`) + 가격**을 표시한다. `price === null`이면 "가격 정보 없음"을 표기한다. **셀프 배지**를 렌더한다(`isSelf`는 응답·인터페이스에 이미 존재하나 현재 미사용 — `app/search/page.tsx:11`).
  - **정렬 결정**: `order('name')` 유지. 이름 검색의 예측성(가나다순 탐색)을 지키고, 가격 유무로 순서가 바뀌는 혼란을 피한다. 가격 없음 행의 시각 처리(흐림 등)는 ux-designer 단계에서 확정.
  - 검색 페이지 안에 별도 유종 전환 UI는 **넣지 않는다**(홈 store를 따라가기만 — research §6-6 최소 범위 권장. 홈과 동일 유종이므로 전환 UI 없이 일관성 확보).
- **수용 기준(AC)**:
  1. 홈 필터바에서 **경유(D047)** 선택 → 검색 진입 → 2글자 이상 입력 시, 결과 각 행의 가격이 해당 주유소의 **경유가**로 표시되고 행에 "경유" 라벨이 보인다(홈 지도 마커의 경유가와 동일 값).
  2. 홈에서 **LPG(C004)** 선택 후 LPG 전용 충전소 상호(예: "○○충전소")를 검색하면 해당 충전소가 결과에 노출되고 LPG 가격이 표시된다. (현재: 0건 — 버그 재현 후 수정 확인)
  3. **휘발유 모드**에서 같은 LPG 전용 충전소 이름을 검색해도 업소가 결과에 노출되며, 가격 자리에 "가격 정보 없음"이 표시된다.
  4. `is_self = true`인 주유소의 결과 행에 "셀프" 배지가 표시된다.
  5. `GET /api/search?q=…&product=D047` 응답의 각 result에 `product: 'D047'`과 경유 `price`(없으면 `null`)가 담긴다. `product=XXXX`(비유효 코드)는 400을 반환한다.
  6. Mock 모드(`NEXT_PUBLIC_USE_MOCK=true`)에서 외부 키 없이 1~4와 동일한 동작(유종별 mock 가격)이 확인된다.

### FR-2: 상세 가격추이 유종 탭 (+ 주유기록 단가 B027 고정 수정)

- **설명**:
  - `app/station/[id]/page.tsx`(async 서버 컴포넌트)의 가격 추이 섹션(`:110~113`)을 **클라이언트 래퍼 컴포넌트 신설**로 교체한다. 래퍼가 탭 상태(`useState<ProductCode>`)를 갖고 `PriceHistoryChart`에 `product`를 내려보낸다 — 차트는 `[stationId, product]` deps로 자동 재조회하고, history API도 `?product=`를 이미 지원하므로 추가 배선 불필요(research §1.3 검증 완료).
  - **탭 노출 유종**: `detail.prices`에서 **가격이 non-null인 유종만** `PRODUCT_ORDER` 순으로 노출한다. K015(실내등유)는 sync가 적재하지 않아 자연 미노출(빈 차트 방지, research §1.6). non-null 유종이 1개뿐이면 탭 UI 없이 해당 유종 차트만 표시. 전부 null이면(가격 전무 업소) 현행 동작(휘발유 차트 1개)을 유지한다.
  - **진입 시 기본 선택**: 래퍼에서 `useMapStore().product`를 읽어 기본 탭으로 삼되, 해당 주유소에 그 유종 가격이 없으면 가격 있는 첫 유종(PRODUCT_ORDER 순)으로 폴백한다.
  - 섹션 제목 하드코딩 `"휘발유 30일 추이"`를 선택 유종 라벨 반영(`{PRODUCT_LABEL[선택유종]} 30일 추이`)으로 바꾼다.
  - **주유기록 단가 연동**: CTA의 `FuelLogButton`(`:134`) `unitPrice`를 `detail.prices.B027` 고정에서 **선택 유종 단가**로 바꾼다. 추이 탭과 CTA 섹션이 떨어져 있으므로 상태 공유 방식은 구현 재량으로 하되 다음 두 옵션 중 택1: (a) 래퍼가 `detail.prices` 전체를 받아 추이 섹션과 FuelLogButton을 함께 렌더(서버 컴포넌트 섹션 순서 재배치 수반), (b) 상세 페이지 스코프의 경량 공유 상태(컨텍스트/스토어). 어느 쪽이든 아래 AC-5의 행위를 만족해야 한다. `FuelLogButton`의 "휘발유 현재가" 주석(`components/station/FuelLogButton.tsx:18`)도 갱신한다.
  - 유종별 현재가 리스트(`:85~102`)는 이미 전 유종을 표시하므로 변경하지 않는다.
- **수용 기준(AC)**:
  1. 홈에서 **경유** 선택 상태로 경유 취급 주유소 상세에 진입하면, 추이 섹션 제목이 "경유 30일 추이"이고 경유 탭이 활성 상태이며 차트가 경유 데이터를 표시한다.
  2. 탭에는 그 주유소의 **가격이 있는 유종만** 노출된다(예: 휘발유/경유만 파는 곳에서 LPG·실내등유 탭이 보이지 않는다).
  3. 탭 전환(예: 휘발유→경유) 시 차트가 해당 유종의 30일 데이터로 갱신되고 제목 라벨도 함께 바뀐다(전환 후 정상 네트워크 기준 수 초 내 표시, 로딩 상태 노출 허용).
  4. 홈에서 **LPG** 선택 상태로 LPG를 취급하지 않는 주유소 상세에 진입하면, 가격 있는 첫 유종 탭으로 폴백해 표시된다(빈 차트가 기본으로 뜨지 않는다).
  5. 경유 탭이 선택된 상태에서 "여기서 주유"를 열고 리터 30을 입력하면 추정 금액이 **경유 단가 × 30** 기준으로 표시된다(현재: 휘발유 단가 기준).
  6. Mock 모드에서 외부 키 없이 1~5의 탭 전환·차트 갱신이 동작한다.

### FR-3: 셀프 필터 칩

- **설명**:
  - `stores/map.ts`에 `selfOnly: boolean` + `toggleSelfOnly` 추가(기존 `brands`/`toggleBrand` 패턴과 동형).
  - `components/ui/FilterBar.tsx` 스크롤 칩 영역(EV 칩 옆)에 "셀프" 토글 칩 추가 — 기존 칩과 동일 스타일 + `aria-pressed`. 노출 조건은 `BrandFilter`와 동일하게 **gas 레이어에서만**(EV 충전소에는 셀프 개념이 없음). EV로 전환해도 `selfOnly` 상태는 유지되며 gas 복귀 시 다시 적용된다.
  - `app/page.tsx:527~564`의 `visible*` useMemo들(`visibleStations` / `visibleNearbyTop10` / `visibleNearbyStations` / `visibleAllStations`)에 `selfOnly` 필터를 `brandSet`과 동일한 자리에서 결합한다(`.filter((s) => !selfOnly || s.isSelf)`). 클라이언트 필터만으로 충분 — 서버 재조회 불필요(`isSelf`는 bbox/radius/회색 점 응답에 실재, `lib/db/queries.ts:49,85,108`).
  - 브랜드 필터와 동일한 원칙: **표시 집합(마커·하단 시트)만 좁히고**, 1km 알람 판정 등 '내 주변 데이터' 본연의 동작(원본 `radiusStations` 사용부)에는 적용하지 않는다.
  - **예외**: 전국 TOP10 크라운 핀(`visibleNationalTop10`)은 `NationalTop10Item`에 `isSelf`가 없어 이번 범위에서 **셀프 필터 미적용**(Out 참조). 등유(K015) 칩도 범위 제외(백로그 유지, 근거 research §1.6 — sync가 K015를 적재하지 않아 빈 지도가 됨).
- **수용 기준(AC)**:
  1. 홈 필터바(gas 레이어)에 "셀프" 칩이 보이고, 탭 시 활성 스타일로 바뀌며 `aria-pressed="true"`가 된다. 다시 탭하면 해제된다.
  2. 셀프 칩 활성 시 지도 가격 마커·회색 점·하단 시트 목록이 **셀프 주유소만** 표시된다(비셀프 마커가 화면에서 사라진다). 해제 시 전체가 복원된다.
  3. 브랜드 필터와 동시 적용(AND) — 예: "GS칼텍스 + 셀프" 선택 시 GS칼텍스 셀프 주유소만 마커로 남는다.
  4. 셀프 칩 활성 상태에서 유종 전환·지도 패닝을 해도 필터가 유지된다.
  5. EV 레이어에서는 셀프 칩이 노출되지 않고, gas 레이어 복귀 시 이전 셀프 상태가 그대로 적용된다.
  6. (명시적 예외 — QA가 버그로 오인하지 않도록) 전국 TOP10 크라운 핀은 셀프 필터 활성 중에도 그대로 표시된다.

## 범위

### 포함(In)
- `/api/search` product 파라미터 + left join화 + mock 유종 반영 (FR-1)
- 검색 페이지 product 전달·유종 라벨·셀프 배지·가격 없음 표기 (FR-1)
- 상세 추이 클라이언트 래퍼 + 유종 탭(non-null만) + 기본 유종 store 연동 + 폴백 (FR-2)
- 주유기록 버튼 단가의 선택 유종 연동 (FR-2)
- `selfOnly` 스토어 상태 + 셀프 칩 + 지도/시트 클라이언트 필터 (FR-3)

## 미해결/리스크

1. **PostgREST left join + 임베드 필터 실동작** (research §6-2 승계, 영향: FR-1 핵심): `prices_latest(product, price)`(non-inner) + `.eq('prices_latest.product', p)`가 "부모 행 유지 + 임베드만 필터"로 동작하는 게 표준이나 supabase-js 버전별 미세 차이 가능. **대응**: 구현 착수 시 실 Supabase로 1회 검증(AC-2·3 시나리오). 불일치 시 2쿼리 방식(stations 검색 → prices_latest in+eq)으로 전환 — 동작이 명확하고 비용 증가는 소폭.
2. **K015 잔존 행 가능성** (research §6-1 승계): 프로덕션 `prices_latest`에 과거 sync/Opinet 폴백 경유 K015 행이 있을 수 있음. **대응**: FR-2 탭을 "non-null 유종만"으로 정의해 자동 흡수(있으면 탭이 뜨고 이력도 그만큼 표시, 없으면 미노출 — 어느 쪽도 깨지지 않음).
3. **TOP10 크라운 핀 isSelf 부재** (research §6-4 승계): 이번엔 미적용으로 확정(FR-3 AC-6에 예외 명시, Out에 백로그 이관). 셀프 필터 중 크라운 핀이 남는 게 사용자에게 혼란일 수 있어, ux-designer 단계에서 필요 시 안내 처리 검토.
4. **FuelLogButton 상태 공유 설계** (research §6-5 승계): 래퍼 범위 확장(섹션 재배치 수반) vs 경량 공유 상태 — 구현 재량으로 위임하되 FR-2 AC-5의 행위로 결과를 고정. 섹션 재배치를 택할 경우 모바일 레이아웃 회귀 확인 필요(DoD §10-5).
5. **검색 데이터 캐시 60초 stale** (research §5-1 승계): 데이터 캐시 키는 PostgREST URL 전체이고 product가 URL에 포함되므로 유종별 캐시가 자연 분리 — 추가 작업 불필요. 60초 지연은 NFR-3(1시간) 이내로 허용. 만약 stale 혼선이 재현되면 `getSupabaseFresh` 전환 전례(커밋 15c5828/4cc93f5)를 따른다.
6. **가격 없음 행의 검색 UX**: 이름순 유지로 결정했으나(FR-1), "가격 정보 없음" 행이 상단에 섞일 때의 시각 처리(흐림/후순위 배지 등)는 ux-designer 판단 영역. AC는 "노출 + 문구 표기"까지만 고정.
7. **세그먼트 규모 수치의 한계**: "경유+LPG ≈ 등록차 44%"는 등록 통계 기반 추정이며, 본 서비스 사용자 중 비휘발유 비중은 미계측(계측 차원 추가는 Out). 이번 근거는 구조적 결함(검색 누락·단가 오계산) 자체로 충분하다고 판단.
