# 조사·기획: 교통정보 제공

> 2026-08-27. 코드 수정 없음(조사 시점 기준). 모든 주장에 근거(파일 경로 / 실측 / URL)를 달았고,
> 확인하지 못한 것은 "미확인"으로 표시했다.

## 0. 결론 요약

**교통정보 자체를 제공하는 것으로는 차별화가 되지 않는다.** 카카오맵·티맵·네이버지도가 이미
같은 원천(ITS·통신사 프로브)으로 더 잘한다. 우리가 교통정보를 얹어도 "그 앱들보다 나쁜 지도"가 될 뿐이다.

대신 **이 앱만 답할 수 있는 질문**이 있다:

> **"저기 500원 싼 주유소, 지금 가면 진짜 이득인가?"**

가격은 우리만 갖고 있고, 시간·거리는 교통정보가 준다. 둘을 합치면 남이 못 만드는 답이 나온다.
교통정보는 **목적이 아니라 재료**로 쓰는 게 맞다.

우선순위:

| 순위 | 항목 | 비용 | 근거 |
|---|---|---|---|
| **1** | 경로 소요시간 노출 (이미 받아놓고 버리는 값) | 거의 0 | §2-B 실측 |
| **2** | "우회 이득" 계산 (절감액 − 추가 연료비, 추가 시간 병기) | 중 | §3 |
| **3** | 지도 교통 오버레이 토글 | 거의 0 | §2-A 실측 |
| — | ITS 돌발상황(사고·공사) 연동 | 중~상 | §2-C, 지금은 보류 |

## 1. 현재 상태 (코드 근거)

- **카카오 길찾기를 이미 쓴다.** `lib/route/directions.ts` — `apis-navi.kakaomobility.com/v1/directions`
  호출, `{ path, distance, duration }` 반환. 서버 전용 키(`KAKAO_REST_API_KEY` ↦ `KAKAO_CLIENT_ID`).
- **호출부는 `route-cheapest` 한 곳.** `app/api/route-cheapest/route.ts:83`.
- **카카오맵 SDK가 이미 로드된다.** `components/map/KakaoMap.tsx`.
- **연비 산출 경로가 있다.** `vehicles` 테이블에는 연비 컬럼이 없지만
  (`supabase/migrations/0006_vehicles.sql:5-12`), `fuel_logs`(주행거리 `odometer` + 주유량)로
  평균 연비를 이미 계산해 차계부 리포트에 보여주고 있다(`components/fuel/FuelReport.tsx`).

## 2. 데이터 소스 검증

### A. 카카오맵 교통정보 오버레이 — **현재 키로 즉시 사용 가능(실측 확인)**

프로덕션(onek1000.kr)에 로드된 SDK에 직접 질의한 결과:

```
MapTypeId 값: ROADMAP, NORMAL, SKYVIEW, HYBRID, OVERLAY, ROADVIEW,
              TRAFFIC, TERRAIN, BICYCLE, BICYCLE_HYBRID, USE_DISTRICT
Map 메서드  : getMapTypeId, setMapTypeId, addOverlayMapTypeId, removeOverlayMapTypeId
적용 시도   : addOverlayMapTypeId(TRAFFIC) 호출 성공, remove 존재
```

강남 일대에서 실제로 렌더되는 것까지 스크린샷으로 확인했다 — 빨강(정체)/노랑(서행)/초록(원활)
방향 화살표. **새 API·새 키·추가 비용이 없다.**

⚠️ **다만 밀도가 매우 높다.** level 5에서 화면이 화살표로 가득 차 주유소 가격 마커와 정면으로
경쟁한다. 항상 켜두면 이 앱의 본질(가격 비교)을 가린다 → **기본 OFF + 토글**이어야 한다.

### B. 카카오 길찾기 `duration` — **이미 받고 있는데 버리고 있다(실측 확인)**

`fetchRoadRoute` 는 `{ path, distance, duration }` 을 돌려주는데,
`app/api/route-cheapest/route.ts` 의 응답은 `{ stations, buffer, product, path, usedRoad }` 뿐이다.
**`distance` 와 `duration` 이 응답에 담기지 않는다.** 화면에 소요시간을 보여준 적이 없다.

카카오 내비의 `duration` 은 실시간 교통을 반영한다(내비 서비스의 본질이므로). 즉 **추가 호출 없이**
"이 경로 지금 몇 분" 을 보여줄 수 있다.

⚠️ **미확인**: 구간별 교통 상태(`road_details` / `traffic_state` 같은 필드)가 응답에 포함되는지는
확인하지 못했다. 공식 문서가 SPA라 본문을 읽지 못했고, 로컬에 서버 키가 없어 실제 호출도 못 했다.
**운영 키로 응답 한 번만 찍어보면 즉시 확정된다** — 있으면 "경로 위 정체 구간 강조"까지 공짜로 된다.

### C. ITS 국가교통정보센터 — 무료 개방, 다만 지금은 과하다

[its.go.kr/opendata](https://www.its.go.kr/opendata/) 에서 소통정보(VDS), **돌발상황정보**(사고·고장·
낙하물·침수·기상·공사), CCTV, VMS 등을 파일·OpenAPI로 무료 제공한다.
[국토교통부_돌발상황정보](https://www.data.go.kr/data/15040465/openapi.do) 는 data.go.kr 에도 올라와 있어
**기존 EV/세차장 연동 패턴(`lib/ev/client.ts` → `sync-ev`)을 그대로 재사용할 수 있다.**

그럼에도 **지금은 보류를 권한다**:
- 사고·공사 정보는 "지금 이 앞이 막힌다"를 알려주지만, 우리 앱은 **주행 중에 보는 앱이 아니다**
  (내비가 아니다). 사용자는 출발 전에 싼 주유소를 고르고 앱을 닫는다.
- 돌발정보를 실시간으로 의미 있게 쓰려면 결국 내비 수준의 화면·알림이 필요하다. 범위가 급격히 커진다.
- A·B 로 얻는 것에 비해 비용이 훨씬 크다.

### D. 한국도로공사 — 이미 연동돼 있음

고속도로 휴게소 주유소를 이 원천으로 적재한다(`services/highway-sync/`).
[고속도로 공공데이터 포털](https://data.ex.co.kr/openapi/intro/introduce02)에 실시간 소통 API도 있다.
**"고속도로 정체 + 휴게소 주유"** 조합은 우리가 유리한 자리지만, 이것도 C와 같은 이유로 후순위다.

## 3. 제안

### 1단계 — 경로에 소요시간 노출 (거의 공짜)

`route-cheapest` 응답에 `distance` / `duration` 을 실어 보내고 경로 모드 표시줄에 함께 보여준다.
지금은 `fetchRoadRoute` 가 돌려준 값을 그냥 버리고 있으므로 **추가 API 호출이 0** 이다.

> 출발 → 도착 · 32km · **48분** · 최저가 3곳

### 2단계 — "우회 이득" 계산 (이 앱의 고유 각도)

경로에서 벗어난 주유소를 고를 때, 절감액만 보여주면 절반만 말하는 것이다. 우회하면 기름과 시간이 든다.

```
절감액      = (경로 평균가 − 이 주유소 가격) × 주유량
추가 연료비 = (추가 거리 km ÷ 연비) × 이 주유소 가격
순이득      = 절감액 − 추가 연료비        ← 여기에 "+ 12분" 을 병기
```

- **연비**: 차계부에 기록이 있으면 그 사용자의 평균 연비, 없으면 전국 평균값 폴백.
- **추가 거리·시간**: 경유지를 넣은 길찾기 1회로 얻는다(경로당 1회, 후보 전체가 아니라
  **사용자가 탭한 주유소에 대해서만** 호출해 쿼터를 지킨다).
- **표현 원칙**: 단정하지 않는다. 연비·주유량은 가정값이므로 `"연비 12km/L 기준"` 처럼 전제를 함께 쓴다.
  세차 지수·주유 타이밍에서 쓰는 톤과 같게 간다.

이게 진짜 차별점이다. **"싼 주유소"는 누구나 보여주지만 "가서 넣는 게 이득인지"는 아무도 안 알려준다.**

### 3단계 — 지도 교통 오버레이 토글

`addOverlayMapTypeId(TRAFFIC)` 한 줄. **기본 OFF**, 필터바 또는 지도 우측 컨트롤에 토글.
켠 상태는 로컬 저장(레이어 선택과 동일 패턴).

⚠️ 켜면 가격 마커 가독성이 확실히 떨어진다. 켰을 때 마커를 축약(가격 숨김·점만)하는 등의
보완이 필요할 수 있다 — 디자인 확인 대상.

## 4. 하지 말아야 할 것

- **범용 교통정보 앱 흉내.** CCTV·VMS·전광판 같은 걸 붙이면 카카오맵 열화판이 된다.
- **경로 결과를 DB에 저장.** 카카오 약관은 실시간 호출 기반 사용만 허용한다
  (같은 이유로 `lib/geocode/reverse.ts` 는 표시 전용으로 못 박아 두었다). 길찾기 결과 캐싱은
  **약관 확인 전까지 하지 않는다** — 카카오 데브톡에 같은 질문(자체 DB 저장·재사용) 스레드가 있으니
  도입 전 확인이 필요하다.
- **주행 중 알림.** 내비가 아니고, 운전 중 알림은 안전 문제와 직결된다.

## 5. 미확인 사항 (진행 전 확인 필요)

1. **카카오 길찾기 응답에 구간별 교통 상태가 있는가** — 운영 키로 1회 호출해 확인.
   있으면 "경로 위 정체 구간" 강조가 공짜로 붙는다.
2. **길찾기 호출 쿼터·요금** — 2단계는 사용자가 주유소를 탭할 때마다 1회 호출한다.
   현재 사용량(경로 검색당 1회)보다 늘어나므로 상한 확인이 필요하다.
3. **경로 결과 저장 가능 여부** — §4 참고. 저장 불가면 매번 호출해야 하고 이는 2번과 직결된다.
