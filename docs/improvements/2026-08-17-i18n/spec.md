# 설계 명세: 다국어(i18n) 도입 — 한국 체류 외국인·관광객 대상 UI 번역

> 작성: 2026-08-17 · 브레인스토밍 합의 결과 · 구현 계획(plan)은 별도 문서

## 목적과 대상

**대상은 한국에 있는 외국인 운전자다** — 체류 외국인과 렌터카를 모는 관광객. 해외 검색 유입(SEO)이
목적이 아니다. 이 구분이 설계 전체를 결정한다: URL에 로케일을 넣지 않고, 국내 SEO 자산인 지역
페이지는 한국어 정적 페이지로 그대로 둔다.

**지원 로케일**: `ko`(기본·폴백) / `en` / `zh`(간체) / `ja`

## 현황 (착수 시점 실측)

| 항목 | 값 |
|---|---|
| 페이지 / 컴포넌트 | 29 / 74 |
| 한글 문자열이 든 `.tsx` | 115개 (lib·types 포함 254개) |
| 고유 한글 문자열 리터럴 | 약 575개 |
| i18n 라이브러리 / 미들웨어 | 없음 / 없음 |
| 루트 레이아웃 | `<html lang="ko">`, `locale: 'ko_KR'` 고정 |
| `Header` 렌더 위치 | `app/page.tsx` 한 곳 (루트 레이아웃 아님) |

렌더링 모드:

| 페이지 | 모드 | 로케일 쿠키를 서버에서 읽을 수 있나 |
|---|---|---|
| `/station/[id]`, `/ev/[statId]`, `/carwash/[id]` | 이미 `force-dynamic` | 가능 (추가 비용 0) |
| `/`, `/search`, `/route` | 클라이언트 컴포넌트 + 정적 프리렌더 | 불가 → 동적 전환 필요 |
| `/my/*` | 서버, 세션 사용(이미 동적) | 가능 |
| `/regions/*` (291p) | SSG + ISR | 불가 (그리고 유지해야 함) |

## 범위

**번역한다** — 핵심(지도·필터·주유소/EV/세차장 상세·검색·경로) + 마이페이지·주유기록·차량 + 로그인.
문자열 등장 기준 약 803개, 고유 키는 400개 안쪽으로 예상.

**번역하지 않는다** (각각 이유가 다르다):

- **`/admin/*`** — 운영자 본인만 본다. 순수 낭비.
- **`/legal/*`** — 약관·개인정보처리방침은 법적 효력이 있는 문서다. 번역본이 원문과 어긋나면 분쟁 시
  책임 문제가 된다. 개발 작업으로 처리할 성격이 아니며, 필요해지면 법무 검토를 거쳐 별도로 진행한다.
- **`/billing`, `/pricing`** — 토스페이먼츠 결제창 자체가 한국어·국내 카드 기준이라 앞단만 영어로
  바꾸면 흐름이 중간에 끊긴다.
- **`/regions/*`** — 국내 검색 유입 자산(SSG 291p). 외국인이 `/regions/seoul/0101`을 탐색할 일이 없다.

## 아키텍처

### 라이브러리: next-intl (URL 라우팅 없이 쿠키 모드)

직접 구현(React Context) 대비 선택 이유는 **퇴로**다. 지금은 SEO가 목적이 아니라 URL 로케일을 의도적으로
미뤘는데, 나중에 필요해지면 next-intl은 설정 변경 수준으로 `/en/...` 라우팅으로 올릴 수 있다. 직접 구현은
그 시점에 라우팅을 새로 짜야 한다. 아낀 의존성(~15KB)보다 이 퇴로의 값이 크다.

클라이언트 전용(i18next)은 배제했다 — 모든 화면에서 한국어가 먼저 보였다가 바뀌는데, 이건 외국인
사용자에게 정확히 잘못된 첫인상을 준다. 기능의 목적 자체를 훼손한다.

### 경계: 라우트 그룹 `app/(intl)/`

**제약**: 루트 레이아웃에서 `cookies()`를 읽으면 하위 트리 전체가 동적 렌더링으로 전환되어
`/regions` 291개 SSG가 사라진다. 따라서 로케일 읽기를 루트가 아닌 **번역 대상 서브트리**로 내린다.
라우트 그룹은 URL에 영향을 주지 않아 주소는 전부 그대로다.

```
app/
  layout.tsx        정적 유지. <html lang="ko">, SessionProvider·계측만
  (intl)/           신설 — 쿠키 읽기 + NextIntlClientProvider + force-dynamic
    page.tsx        ← 기존 app/page.tsx (홈/지도)
    search/  route/  station/[id]/  ev/[statId]/  carwash/[id]/  my/*  auth/*
  regions/          그대로 (SSG+ISR, 한국어)
  legal/  admin/  billing/  pricing/    그대로 (한국어)
```

루트 레이아웃에 공용 번역 크롬이 없다는 점이 이 분리를 가능하게 한다 — `Header`는 `app/page.tsx`에서만
렌더되므로, 그룹 밖 페이지가 번역된 헤더를 잃는 문제가 발생하지 않는다.

### 흐름

1. **`middleware.ts` (신설)** — `NEXT_LOCALE` 쿠키가 없으면 `Accept-Language`를 파싱해 지원 목록과
   매칭하고, 매칭 실패 시 `ko`. 쿠키를 심고(max-age 1년, SameSite=Lax, **httpOnly 아님** — 전환 UI가
   읽어야 한다) 통과. matcher에서 `/api/*`와 정적 자산 제외.
2. **`i18n/request.ts`** — 쿠키에서 로케일을 읽어 해당 메시지 JSON을 반환.
3. **`(intl)/layout.tsx`** — `force-dynamic`. 서버에서 로케일·메시지를 읽어 `NextIntlClientProvider`로
   감싼다. **서버가 첫 HTML을 이미 해당 언어로 렌더하므로 깜빡임이 없다.**
4. 서버 컴포넌트는 `getTranslations()`, 클라이언트는 `useTranslations()`.

### 감수하는 대가 두 가지

- **`<html lang>`은 정적 루트 레이아웃에 있어 서버에서 못 바꾼다.** `(intl)` 프로바이더에서 클라이언트로
  `document.documentElement.lang`을 맞춘다. 스크린리더·브라우저 번역기 인식용이며, 한국어 SEO 페이지는
  `ko`로 남으므로 검색 영향이 없다.
- **`/`·`/search`·`/route`가 정적 → 동적으로 바뀐다.** 세 페이지 모두 데이터를 클라이언트에서 가져오므로
  SSR은 껍데기만 렌더한다. 이것이 깜빡임을 없애는 대가다.

## 메시지 카탈로그

`messages/{ko,en,zh,ja}.json`. `ko.json`이 원본이며 나머지는 여기서 파생한다.

```
common   버튼·상태·에러 (닫기, 저장, 불러오는 중, 다시 시도)
map      지도·필터·마커 범례·바텀시트
station  주유소 상세 (가격, 편의시설, 리뷰 UI, 길안내)
ev       충전소        carwash  세차장
search   검색          route    경로 최저가
my       마이페이지·주유기록·차량·관심지역
auth     로그인·비밀번호 재설정
```

**폴백**: 키가 없으면 **한국어로 대체**한다. 키 문자열이 화면에 노출되면 안 된다. next-intl 기본 동작은
키를 그대로 뿌리거나 에러를 던지므로 `getMessageFallback`·`onError`를 설정해 조용히 `ko`로 떨어뜨리고,
개발 환경에서만 경고를 남긴다. 번역이 덜 된 상태로 배포돼도 화면이 깨지지 않는다.

### 코드 상수를 카탈로그로 이전

관광객 체감이 가장 큰 부분이다. 현재 `types/station.ts` 등에 한글이 박혀 있다.

| 상수 | ko | en |
|---|---|---|
| `PRODUCT_LABEL` | 휘발유 / 경유 / LPG / 고급휘발유 | Gasoline / Diesel / LPG / Premium |
| `BRAND_LABEL` | SK에너지 / 알뜰주유소 / 고속도로 | SK Energy / Alddle / Highway |
| `SIDO_NAME` | 서울 / 경기 / 제주 | Seoul / Gyeonggi / Jeju |
| 세차 유형 | 셀프 / 손세차 / 자동 | Self / Hand / Automatic |

코드→라벨 매핑만 카탈로그로 옮기고 상수에는 코드를 남긴다.

**절대 건드리지 않는 것**: `SIDO_SLUG`(URL 슬러그), `SidoCode`·`BrandCode`·`ProductCode`(DB 값).
이들은 데이터 식별자이지 표시용 라벨이 아니다. 변경하면 URL과 DB 조회가 깨진다.

### 번역하지 않는 콘텐츠 (DB 원본)

- **주유소·충전소·세차장 이름과 주소** — 오피넷/행안부 원본 한글. **한글로 두는 것이 맞다**: 현장 간판이
  한글이고 내비에 찍을 때도 한글 주소가 필요하다. 번역하면 대조가 불가능해진다.
- **공지(`0030_notices`)·사용자 리뷰** — 운영자·사용자가 쓴 한국어 원문. 그대로 노출한다.

결과적으로 화면은 **"번역된 UI + 한글 고유명사"** 조합이 된다. 이는 타협이 아니라 이 용도에 맞는
형태다 — 외국인 사용자에게 필요한 것은 "이 버튼이 뭘 하는지"이지 "이 주유소 이름의 영어 표기"가 아니다.

### 숫자·날짜

next-intl의 `Intl` 포매터를 사용한다. 가격은 `₩1,650` 형태로 통일하고, 날짜는 로케일 규칙을 따른다
(`2026. 8. 17.` ↔ `Aug 17, 2026`).

## 언어 전환 UI

**헤더에만 둔다.** 프로필 설정에는 넣지 않는다.

이유: `/my`는 미로그인 시 로그인 페이지로 리다이렉트된다(`app/my/page.tsx:48`). 관광객 대부분은 가입 없이
지도만 쓰므로, 프로필에만 두면 **자동 감지가 어긋났을 때 되돌릴 방법이 없는 상태로 갇힌다** — 로그인하려면
그 로그인 화면부터 못 읽는 언어로 떠 있다. 헤더는 이미 검색·경로·마이페이지 아이콘이 있어 지구본 아이콘
하나가 자연스럽게 들어간다.

- **목록은 각 언어를 그 언어로 표기한다**: 한국어 / English / 中文 / 日本語. 못 읽는 언어로 적힌 목록은
  쓸모가 없다.
- 선택 시 쿠키를 갱신하고 `router.refresh()`로 서버 컴포넌트를 새 언어로 다시 렌더한다.
- **저장은 쿠키만.** 로그인 사용자 DB 저장은 기기 간 동기화가 되지만 마이그레이션이 늘고, 주 사용자가
  비로그인이라 값이 작다. 필요해지면 나중에 올린다.

## 계측

미들웨어가 감지한 언어를 첫 방문 1회 이벤트로 남긴다. 실제 방문자 언어권 분포가 쌓이면 4개 언어 유지가
맞는지, 어디에 번역 품질을 더 쏟을지 데이터로 판단할 수 있다.

## 검증

문자열이 많아 **빠뜨림**이 주된 실패 모드다. 점검 스크립트 두 개를 만든다.

- **`i18n:check`** — `ko.json` 키 집합 대비 `en/zh/ja`의 누락·잉여 키를 출력. *번역 완료 판정 기준.*
- **`i18n:scan`** — `(intl)` 그룹 안에 남은 하드코딩 한글 리터럴을 출력. *마이그레이션 완료 판정 기준.*

여기에 typecheck / lint / build, 그리고 헤드리스 Chrome + CDP 스크린샷으로 4개 언어 주요 화면을 눈으로
확인한다(브라우저 확장이 이 앱 페이지에 스크립트를 주입하지 못하므로 CDP 경로를 쓴다).

**회귀 관점에서 반드시 확인할 것**: 작업 후에도 `/regions/*`가 SSG 291개로 유지되는지 빌드 출력으로
확인한다. 이 설계의 가장 큰 리스크가 라우트 그룹 경계를 잘못 그어 SSG가 무너지는 것이다.

## 구현 순서

단계마다 커밋해 중간에 멈춰도 앱이 정상 동작하게 한다.

1. **인프라** — next-intl 설치, `i18n/request.ts`, `middleware.ts`, `(intl)` 라우트 그룹 이동, 프로바이더.
   *화면 변화 0, 한국어만 존재.* 이 단계에서 SSG 291개 유지를 빌드로 확인한다.
2. **라벨 상수 이전** — `PRODUCT_LABEL`·`BRAND_LABEL`·`SIDO_NAME`·세차 유형.
3. **화면별 문자열 추출** — 지도 → 주유소 상세 → EV/세차장 → 검색/경로 → 마이페이지 → 로그인.
   *각 단계 후 한국어 화면이 그대로인지 확인.*
4. **언어 전환 UI** — 헤더 지구본.
5. **번역** — en 먼저, 그다음 zh/ja.

## 리스크·미해결

- **번역 품질**: en/zh/ja 초벌은 생성하되, **중국어·일본어는 사람 검수를 권한다.** 번역문이 어색한지
  자체 판단이 어렵고, 주유 도메인 용어(셀프주유, 알뜰주유소, 고급휘발유)는 직역하면 현지에서 통하지 않는
  경우가 많다.
- **라우트 그룹 이동 시 상대 경로 임포트**: `@/` 별칭은 안전하지만 이동 디렉터리 내부의 상대 임포트는
  깨질 수 있다. 1단계에서 typecheck로 잡는다.
- **`(intl)` 그룹의 `force-dynamic`이 홈 트래픽 비용을 올린다.** 홈이 최다 트래픽 페이지이므로 배포 후
  응답시간·비용을 관찰한다. 문제가 되면 홈만 정적으로 되돌리고 깜빡임을 감수하는 선택지가 남아 있다.
- **`/regions`가 한국어로 남아 언어 불일치가 생긴다** — 영어 사용자가 지역 페이지로 들어가면 한국어를
  본다. 현재는 의도된 절충이며, 링크 노출을 헤더/네비에서 줄이는 정도로 완화한다.
