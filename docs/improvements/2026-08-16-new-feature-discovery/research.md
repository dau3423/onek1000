2. **실질가(카드 할인 반영) 니즈** — 카드고릴라의 주유할인카드 비교 콘텐츠가 매년 갱신·다수 소비될 만큼 수요 큼. 오일나우도 할인카드·이벤트 큐레이션을 핵심 혜택으로 홍보. "표시가 최저"보다 "내 체감가 최저"가 실제 의사결정 기준.
   - https://m.card-gorilla.com/contents/detail/3610 , https://m.card-gorilla.com/contents/detail/2652
3. **주유 타이밍 니즈** — 오일나우의 최상위 스토어 카피가 "유류세 인하 실시간 반영 중"(타이밍 정보). 우리 예측 카드가 이미 이 니즈를 향하고 있으나 "전국 평균, 옵트인 토글" 수준(§1.1) → 개인 주기와 결합하면 완성됨.

## 4. 후보 상세

### C1. 다음 주유일 예측 + 개인화 주유 타이밍 알림 — **추천 1순위**
- **개요**: 주유기록의 주유 간격(중앙값)·주유량으로 "다음 주유 예상 시기"를 추정하고, 그 시점 전에 유가 예측이 상승(up)이면 "예상 주유일 전에 미리 넣으면 유리" 푸시/홈 배너. 하락(down)이면 "며칠 미루면 유리".
- **개선 아니라 신규인 이유**: 기존 예측 알림(0027)은 전국 공통 브로드캐스트. "내 주유 주기" 기반의 개인화 타이밍 판단·다음 주유일 예측은 존재하지 않는 새 도메인.
- **활용 자산**: `fuel_logs(logged_at, liters)`(0012) + `price_forecast/confidence`(0026) + `forecast_notify` dedupe 패턴(0027) + 웹푸시(`lib/push/webpush.ts`).
- **FR 골격**:
  - FR-1 주유 주기 추정: 최근 N회 logged_at 간격 중앙값(기록 3회 미만이면 미노출) → `GET /api/fuel-logs/next-refuel`.
  - FR-2 홈/마이 "다음 주유" 카드: 예상일 ±α + 그 구간 예측 방향·근거(ForecastCard 재사용).
  - FR-3 개인화 푸시: 예상일 D-3~D-0에 forecast up & confidence≥임계 → 발송(0027 dedupe 로그 재사용, 옵트인 별도 플래그).
- **제약/리스크**: 대상=로그인+주유기록 3회 이상 사용자(현재 소수. 다만 기록 유도의 강력한 명분이 생겨 차계부 활성화와 선순환). 예측은 horizon 14일 방향성이라 "내일 인상" 단정 표현 금지(0027 주석 준수).
- **점수 근거**: 가치 상(체감 절약 직결) / 차별성 상(모델 보유는 우리 고유) / 비용 중(신규 테이블 거의 불필요, 추정 로직+카드+발송 잡) / 리텐션 상(주기적 재방문 트리거 그 자체).

### C2. 세차 묶음: 세차 가능 주유소 필터 + "세차하기 좋은 날" 지수 — **추천 병행(저비용)**
- **개요**: ① 지도 필터에 "세차" 칩(has_carwash) 추가 + 상세·목록 세차 배지. ② 기상청 단기예보(강수확률·황사/미세먼지)로 향후 3~4일 "세차 지수"를 홈에 노출, "오늘 세차 OK + 세차 되는 최저가 주유소" 연결.
- **개선 아니라 신규인 이유**: 세차라는 새 사용 목적(주유 외 방문 이유)을 여는 기능. 필터 칩만이면 개선이지만, 날씨 지수 결합 콘텐츠는 신규 도메인.
- **활용 자산**: `stations.has_carwash`(0001+0010, 회전 보강으로 커버리지 확대 중) + selfOnly 칩 패턴(`FilterBar.tsx`) + data.go.kr 연동 패턴(`lib/ev/client.ts`) — 기상청 단기예보 API(공공데이터포털, 무료).
- **FR 골격**: FR-1 세차 필터 칩(bbox 쿼리에 has_carwash 조건) / FR-2 세차 지수 배치(sync-market처럼 1일 1회 예보 적재) / FR-3 홈 미니카드 "이번 주 세차하기 좋은 날: 토" + 세차 주유소 딥링크.
- **제약**: has_carwash 커버리지(회전 보강 진행률) 실측 필요. 날씨 API 지역 단위(격자) — v1은 시도/현위치 단일 지점이면 충분.
- **점수 근거**: 가치 중~상(세차는 전 운전자 반복 니즈) / 차별성 상(국내 주유 앱 미결합) / 비용 하~중 / 리텐션 중~상(주 1회 확인 습관 + 공유·트윗 소재).

### C3. 주유 할인카드 실질가 (내 카드 반영 체감가)
- **개요**: 사용자가 보유 주유할인카드(상위 15~20종)를 선택 → 지도·목록 가격에 리터당 할인 반영한 "실질가" 병기, 실질가 기준 정렬. 미보유자에겐 "이 카드면 L당 -100원" 추천(제휴 여지).
- **개선 아니라 신규인 이유**: 카드 혜택 DB·실질가 계산이라는 새 데이터 도메인. (백로그 B7 한 줄 항목의 구체화 — `docs/improvements/BACKLOG.md` 2026-08-15행 "데이터 소스 미해결" 지적에 대한 답: 카드고릴라식 공개 혜택 정보를 수동 큐레이션 + 관리자 CMS로 유지)
- **활용 자산**: notices CMS 패턴(`0030_notices.sql`, admin) → 카드 혜택 테이블 관리 화면 재사용 가능. 계산은 클라이언트 단순 뺄셈.
- **FR 골격**: FR-1 `discount_cards` 테이블(카드명, 유종별 할인, 한도, 전월실적 조건) + 관리자 CRUD / FR-2 마이페이지 "내 카드" 선택 / FR-3 목록·상세 실질가 표시(전월실적 미충족 케이스는 툴팁 고지).
- **제약/리스크**: **혜택 데이터 유지보수가 항구 비용**(카드사 개편 잦음). 오표기 시 사용자 클레임. 리터당 정액 할인 외 %·포인트형은 근사치 고지 필요. 카드 목록은 개인정보 아님(카드번호 미수집)이라 규제 부담 낮음.
- **점수 근거**: 가치 상(체감가가 진짜 의사결정 기준) / 차별성 중(오일나우 존재, 단 "지도 실질가 정렬"로 차별 가능) / 비용 대(초기 DB 구축+유지 운영) / 리텐션 상(내 카드 등록 = 락인).

### C4. 여행(경로) 기름값 계산기
- **개요**: 기존 경로 페이지에 "이 여행 기름값 예상: 거리 ÷ 내 연비 × 경로 평균가" 카드 + 경로상 최저가에서 넣으면 절약액. 결과를 공유 이미지로.
- **개선 아니라 신규인 이유**: 경로 최저가(탐색)와 달리 "비용 예측·계획"이라는 새 사용 사례(GasBuddy trip cost 대응).
- **활용 자산**: 카카오 경로 거리(`lib/route/`), `avgKmPerL`(`types/fuel-report.ts:36`, 없으면 유종별 기본 연비 폴백), `rpc_stations_along_path`(0015), OG 이미지 파이프라인(`app/api/og/daily-top10`).
- **FR 골격**: FR-1 경로 결과에 예상 유류비 카드 / FR-2 연비 입력(기록 없으면 수동) / FR-3 공유 카드(A4 공유 루프와 시너지 — 단 그쪽은 별도 백로그).
- **점수 근거**: 가치 중(명절·휴가철 스파이크성) / 차별성 중(국내 주유 앱엔 없음) / 비용 하~중(기존 화면에 카드 추가) / 리텐션 하~중(간헐 사용, 대신 검색 유입·공유 소재 "서울 부산 기름값" 롱테일 SEO 가설).

### C5. 자주 가는 경로 저장 + 경로 최저가 변동 알림
- **개요**: 출퇴근 등 경로를 저장(관심 지역의 경로판) → 주 1회 또는 급락 시 "경로상 최저가가 어제보다 -40원" 푸시.
- **개선 아니라 신규인 이유**: 현 경로 기능은 1회성 조회. "저장된 경로 + 정기 알림"은 새 구독형 자산.
- **활용 자산**: 0015 RPC, interest_regions 저장·알림 패턴(0005), weekly-digest 크론(`app/api/internal/weekly-digest`).
- **FR 골격**: FR-1 `saved_routes`(user_id, 출발/도착 좌표·이름, polyline 캐시) / FR-2 마이페이지 관리 UI / FR-3 크론 배치가 경로별 최저가 스냅샷 비교 → 변동 시 푸시.
- **제약/리스크**: **LBS 고지 확대 필요** — 설명서 §4는 저장 좌표를 "관심 지역"만 명시. 경로(출발·도착=집·회사 추정 가능) 저장은 민감도가 더 높아 설명서·개인정보처리방침 갱신 + 명시 동의 문구 필수. 경로 수 × 크론 부하 상한 설계 필요.
- **점수 근거**: 가치 중(통근자 코어 페르소나 정합) / 차별성 중~상 / 비용 중 / 리텐션 중~상(푸시 채널 확보).

### C6. "가격 다름" 신고 — 경량 크라우드소싱
- **개요**: 상세 페이지에 "현장 가격이 달랐어요" 1탭 신고(선택: 실제가 입력). 신고 누적 시 목록·상세에 "가격 확인 필요" 배지 + trade_dt 강조. 전면 제보(가격 덮어쓰기)는 하지 않음.
- **개선 아니라 신규인 이유**: 사용자 생성 데이터로 공식 데이터를 보정하는 새 신뢰 레이어(GasBuddy·gogo.gs·오일나우의 코어를 우리 규모에 맞게 축소 진입).
- **활용 자산**: 리뷰 파이프라인(0004, 로그인·rate limit), funnel_events 계측(0033).
- **FR 골격**: FR-1 `price_reports` 테이블(station_id, product, reported_price null 허용, user_id, created_at) / FR-2 상세 신고 버튼(일 1회/유저/주유소) / FR-3 24h 내 2건 이상 → 배지 노출·다음 sync 후 자동 해제.
- **제약/리스크**: DAU ~150에선 신고 밀도 부족 → 배지 발동이 드묾(그래서 "덮어쓰기"가 아닌 "배지"로 설계해 저밀도에서도 무해). 허위 신고 어뷰징은 로그인+횟수 제한으로 1차 방어. 주유소 측 항의 가능성(표기는 "확인 필요"까지만).
- **점수 근거**: 가치 중(불만 실증 있음, §3-1) / 차별성 중 / 비용 중 / 리텐션 중(참여 루프 시작점, 향후 포인트 보상과 연결 여지 — 주유로또 문서 `docs/이벤트_주간_주유로또.md` 참조).

### C7. 차량 소모품 교체 알림 (차계부 확장)
- **개요**: 엔진오일·타이어 등 소모품의 마지막 교체 시점(주행거리/날짜) 등록 → odometer 추이로 교체 시기 도래 시 알림.
- **개선 아니라 신규인 이유**: 정비라는 새 도메인(오일나우 정비기록·보험만기 대응). 주유기록 편집 개선이 아님.
- **활용 자산**: `vehicles`(0006), `fuel_logs.odometer`(0012 — 이미 수집 중), 푸시.
- **FR 골격**: FR-1 `maintenance_items`(vehicle_id, 항목, 마지막 교체 km/일, 주기) / FR-2 차량 관리 UI 확장 / FR-3 fuel_log 저장 시 odometer로 도래 판정 → 알림.
- **제약**: odometer 입력률 낮으면(선택 입력) 판정 불가 → 날짜 기반 폴백. 유가 코어 가치와 거리가 있어 우선순위 낮음.
- **점수 근거**: 가치 중 / 차별성 하~중(오일나우가 더 깊음) / 비용 중 / 리텐션 중(락인성 데이터).

## 8. 리스크 / 규제 제약
- **LBS 고지 정합(C5)**: 사업내용설명서 §4·개인정보처리방침은 저장 좌표를 "관심 지역"으로 한정 고지. 경로(집·회사 추정 가능 좌표쌍) 저장 시 문서 갱신 + 명시 동의 없이는 출시 불가.
- **개인 패턴 데이터(C1)**: 주유 주기는 이미 수집된 fuel_logs의 파생 계산이라 신규 수집은 없으나, "행태 분석·맞춤 알림 제공" 목적을 개인정보처리방침에 반영하는 게 안전(커밋 `f9d5d93`이 행동 로그 고지를 이미 확장한 전례).
- **오피넷 의존(C6)**: "가격 확인 필요" 배지가 오피넷 데이터 신뢰도를 공개 지적하는 모양이 될 수 있음 — 출처 협의 관계 고려해 문구를 "주유소 반영 시차" 프레임으로.
- **Opinet 호출 한도**: 어떤 후보도 주유소 단건 실시간 detail 호출을 추가하면 안 됨(일 ~1,500콜, 0010 주석). 모두 기존 sync 데이터로 설계했음.
- **카드 혜택 오표기(C3)**: 금전 관련 오정보 클레임 리스크 — "카드사 최신 약관 우선" 면책 고지 필수.
- **저밀도 크라우드소싱(C6)**: DAU 150에서 배지 발동 빈도 자체가 낮아 체감 효과가 안 날 수 있음(가설) — 계측(0033)으로 신고 건수 확인 후 확대 판단.
