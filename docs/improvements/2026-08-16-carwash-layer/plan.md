## 배경·목표

- **배경**: 현재 세차 관련 데이터는 주유소 부설 세차 플래그(`stations.has_carwash`)뿐이다(research §1, `supabase/migrations/0001_init.sql:20`). FilterBar의 '세차' 칩은 `gas` 레이어에서 `has_carwash` 주유소만 거르는 필터일 뿐, "근처 셀프세차장 어디?"에는 답하지 못한다(research §2).
- **데이터 소스 확정**: 행정안전부 「전국세차장표준데이터」(16,186행, WGS84 좌표 99.96% 채움, 세차유형·업종명 필드, 이용허락 제한 없음·무료·무인증). 카카오/네이버 API는 DB 저장 금지 약관으로 부적합(research §3.1~§3.3).
- **구현 전략**: EV 충전소 레이어 파이프라인(data.go.kr → Supabase → 카카오맵 레이어 + Mock 폴백)을 거의 그대로 복제한다. 외부 인증키가 없어 EV보다 오히려 단순하다(research §5 1안).
- **이번 사이클이 끝나면 사용자가 얻는 것**: 주유소 지도와 같은 화면에서 '세차장' 레이어로 전환해, 전국 독립 셀프·손세차장을 지도에서 찾고 유형별로 걸러 볼 수 있다.

---

## 유저 스토리

1. 운전자로서, 주유 앱 지도에서 주유소를 보다가 **'세차장' 레이어로 전환**해 내 주변 독립 셀프세차장을 지도에서 바로 확인하고 싶다. 그래서 세차하려고 별도 앱/검색을 켜지 않아도 된다.
2. 셀프세차를 선호하는 운전자로서, 세차장 마커를 **셀프/손세차/자동으로 걸러** 원하는 유형만 보고 싶다. 그래서 자동세차만 있는 곳을 헛걸음하지 않는다.
3. 신중한 운전자로서, 공공데이터라 정보가 부정확할 수 있음을 **정직하게 안내**받고, 유형이 미확인이면 미확인이라고 표시되길 원한다. 그래서 앱을 신뢰할 수 있다.

## 기능 요구사항

> 원칙: FR 3개. In 범위는 "레이어 신설 + 최소 유형 필터"까지. 부설 중복 병합·크라우드소싱 보정·시도 매핑·폐업 신고 등은 Out(후속).

### FR-1: 세차장 데이터 파이프라인 (테이블 + sync 크론 + bbox RPC/API)

- **설명**: 「전국세차장표준데이터」 CSV를 우리 DB(`carwash_places`)에 적재하고, 지도 영역(bbox) 조회 API를 제공한다. EV의 `0011_ev_chargers.sql` + `sync-ev/route.ts` + `api/ev/bbox` + `lib/db/ev.ts`(mock 폴백) 4종 세트를 복제한다. 지도/조회는 우리 DB만 보고, 외부 파일 서버는 sync에서만 호출한다.
- **테이블 `carwash_places`(신규 마이그레이션, 예: `0017_carwash_places.sql`)**:
  - `mgmt_no text primary key`(관리번호), `name text not null`(사업장명), `wash_type text`(정규화 enum-유사: `self`/`hand`/`auto`/`unknown`), `road_addr text`·`jibun_addr text`(도로명/지번 주소), `tel text`(세차장전화번호), `weekday_open`·`weekday_close`·`holiday_open`·`holiday_close text`(운영시각, 있을 때만), `fee_info text`(세차요금정보, 있을 때만), `closed_day text`(휴무일, 있을 때만), `lat double precision not null`·`lng double precision not null`, `geom geography(Point,4326) not null` + GiST 인덱스, `biz_type_raw text`(사업장업종명 원문), `data_base_date date`(데이터기준일자 — 노후 행 판정용), `synced_at timestamptz default now()`.
  - **대표자명 컬럼은 스키마에 두지 않는다**(개인정보 최소화, research §5 주의).
  - `rpc_carwash_by_bbox(p_sw_lng, p_sw_lat, p_ne_lng, p_ne_lat, p_limit)` → 마커 필드(mgmt_no, name, wash_type, road_addr, tel, lat, lng, 운영/요금 표시용 필드, data_base_date, synced_at) 반환. `geom && st_makeenvelope(...)` bbox 조건 + `limit`. EV `rpc_ev_chargers_by_bbox` 패턴.
- **sync 크론 `app/api/internal/sync-carwash/route.ts`(신규)**:
  - `Authorization: Bearer ${CRON_SECRET}` 검증(SEC-2). 주 1회 스케줄로 충분(원천 "수시" 갱신, research §5).
  - CSV 다운로드 시 **`Referer: https://file.localdata.go.kr/file/car_wash_info/info` 헤더 필수**(없으면 403, research §3.1·§6-2).
  - **cp949 디코딩** 후 파싱, 청크 upsert(`onConflict: mgmt_no`).
  - **임포트 제외 규칙**: ① 사업장업종명에 '주유'·'충전' 포함 행(부설=기존 `has_carwash` 중복) 제외 → v1은 독립 세차장만. ② 좌표 미채움 행 제외. ③ 한반도 bbox(위도 33~39N, 경도 124~132E) 밖 좌표 행 드랍(이상치 가드, research §6-5).
  - **세차유형 정규화**: `세차유형` 필드 + 사업장명 키워드('셀프'→self, '손세차'·'디테일'→hand, '자동'·'기계식'·'노터치'→auto)를 결합해 self/hand/auto/unknown 4분류로 매핑. 판정 불가는 `unknown`(research §3.1·§6-3).
  - **실패 안전(전체삭제 금지)**: EV의 "미완 sync stale 정리 금지" 교훈을 그대로 따른다. 다운로드/파싱 실패 시 기존 테이블(마지막 성공 스냅샷)을 **그대로 유지**하고 에러를 응답에 기록한다. 테이블 전체 truncate 후 재삽입 방식은 금지.
- **bbox API `app/api/carwash/bbox/route.ts`(신규)** + 도메인 쿼리 `lib/db/carwash.ts`(신규): EV `api/ev/bbox`(49줄) + `lib/db/ev.ts`의 `queryEvChargersByBbox` 패턴 복제(입력 검증 → Redis 캐시 → RPC). rate limit 공개(SEC-3).
- **수용 기준(AC)**:
  - AC-1.1 (**Mock 폴백**): `NEXT_PUBLIC_USE_MOCK=true` 또는 Supabase 미설정 상태에서 `/api/carwash/bbox?swLat=..&swLng=..&neLat=..&neLng=..` 호출 시 500 없이 200과 mock 마커 배열(또는 빈 배열)을 반환한다. 세차장 레이어를 켜도 지도가 크래시하지 않는다(`lib/db/carwash.ts`가 `isSupabaseConfigured()` false 시 mock 반환).
  - AC-1.2 (**미적재/미마이그레이션 안전**): 마이그레이션 미적용 또는 데이터 0건이어도 `/api/carwash/bbox`는 200 + 빈 배열을 반환하고, 프런트 레이어는 "표시할 세차장이 없습니다" 상태로 정상 렌더된다(크래시·무한로딩 없음).
  - AC-1.3 (**개인정보 제외**): `carwash_places` 스키마·RPC 반환·API 응답 어디에도 대표자명 필드가 없다(코드/마이그레이션 grep으로 검증).
  - AC-1.4 (**부설 제외**): 적재된 행은 사업장업종명에 '주유'·'충전'을 포함하지 않는다(샘플 쿼리로 0건 확인). 즉 부설 세차는 이 레이어에 나타나지 않는다.
  - AC-1.5 (**좌표 가드**): 적재된 모든 행의 lat이 33~39, lng이 124~132 범위 안이다(범위 밖 행 0건).
  - AC-1.6 (**실패 안전**): CSV 다운로드가 실패(403/타임아웃)하도록 유도했을 때 sync 응답은 에러를 담아 반환하되, 기존에 적재돼 있던 행 수가 줄지 않는다(전체삭제 없음).
  - AC-1.7 (**bbox 조회 정상**): 데이터 적재 후 서울 도심 bbox로 호출하면 1초 내 마커 배열이 반환되고, 각 마커에 name·wash_type(self/hand/auto/unknown 중 하나)·lat·lng이 포함된다.

### FR-2: 세차장 지도 레이어 UI (레이어 진입점 + 마커 + 팝업)

- **설명**: `MapLayer`에 `'carwash'`를 추가하고, FilterBar에서 세차장 레이어로 진입하는 칩, 지도 마커, 요약 팝업(EvStationPopup 패턴)을 제공한다. **기존 '세차'(부설 필터) 칩과 명확히 구분**한다.
- **상태**: `stores/map.ts:108`의 `export type MapLayer = 'gas' | 'ev'`에 `'carwash'` 추가. `setLayer('carwash')`로 전환. 레이어 전환은 EV와 동일한 상호배타(gas↔ev↔carwash) 방식.
- **진입점(혼동 방지가 핵심)**: FilterBar에 EV 칩 옆에 **'세차장' 칩**(예: `setLayer('carwash')`)을 둔다. 기존 '세차' 칩(부설 `has_carwash` 필터, gas 레이어 전용)과 다음으로 구분한다.
  - 명명: 신규 레이어 진입 칩은 "세차장"(장소=독립 세차장), 기존 부설 필터 칩은 "세차"(부설 옵션) — 라벨을 달리한다. 필요 시 기존 칩을 "주유+세차"로 재명명 제안(§SRS 반영 제안 참조).
  - 배치: 신규 '세차장' 칩은 EV 칩과 같은 "레이어 전환" 그룹(강조 스타일 `aria-pressed`)에, 기존 '세차' 칩은 gas 레이어 전용 필터 그룹에 둔다. carwash 레이어 활성 시 기존 '세차'(부설 필터) 칩·브랜드 필터는 숨긴다(EV 레이어에서 숨기는 것과 동형, `FilterBar.tsx:157,179`).
- **마커**: 세차장 1곳=마커 1개. 주유소/EV 마커와 시각적으로 구분되는 아이콘/색상. 화면당 상한(EV의 `EV_LIMIT=200` 유사).
- **팝업 `components/map/CarwashPopup.tsx`(신규)**: EvStationPopup 패턴 복제. 표시: 이름, **유형 뱃지**(셀프/손세차/자동/유형 미확인), 주소, 전화(있으면 전화걸기 CTA), 운영시각·요금(있을 때만), 길안내 CTA. 운영시각/요금 채움률이 낮으므로(10.1%/5.5%) **값이 있을 때만 노출**한다.
- **수용 기준(AC)**:
  - AC-2.1 (**레이어 전환**): FilterBar의 '세차장' 칩 탭 시 지도가 세차장 레이어로 바뀌어 세차장 마커가 표시되고, 주유소 가격 마커는 사라진다. 칩은 `aria-pressed=true`로 활성 표시된다.
  - AC-2.2 (**부설 칩과 구분**): 세차장 레이어가 활성일 때 기존 '세차'(부설 필터) 칩과 브랜드 필터는 화면에 보이지 않는다. gas 레이어로 돌아오면 다시 보인다. 두 칩의 라벨이 서로 달라 육안으로 구분된다.
  - AC-2.3 (**팝업**): 세차장 마커 탭 시 이름·유형 뱃지·주소가 표시된 팝업이 뜬다. 전화번호가 없는 세차장은 전화 CTA가 렌더되지 않는다(빈 버튼/`undefined` 노출 없음).
  - AC-2.4 (**운영정보 조건부 표기**): 운영시각·요금 데이터가 없는 세차장의 팝업에는 해당 항목 라벨 자체가 나타나지 않는다(빈 값·"undefined"·"null" 노출 금지).
  - AC-2.5 (**유형 미확인 정직 표기**): wash_type=`unknown`인 세차장의 팝업 유형 뱃지는 "유형 미확인"으로 표시된다(공란·오분류 금지).
  - AC-2.6 (**정보 노후 고지**): 세차장 레이어/팝업 어딘가에 "공공데이터 기준이며 실제와 다를 수 있습니다(폐업·정보 변경 가능)" 취지의 정직 고지 문구가 노출된다(research §6-1).
  - AC-2.7 (**Mock 동작**): Mock 모드에서 '세차장' 칩 탭 시 mock 마커가 표시되거나 빈 상태 메시지가 나오며, 콘솔 에러/크래시가 없다.
  - AC-2.8 (**출처 표기**): 정보/팝업에 데이터 출처(행정안전부 전국세차장표준데이터)가 표기된다(SRS §8 출처 표기 관행 준수).

### FR-3: 세차 유형 필터 (셀프/손세차/자동/전체)

- **설명**: 세차장 레이어 활성 시에만 노출되는 유형 세부 필터. 셀프/손세차/자동/전체(미확인 포함) 중 선택. `carwashOnly`(부설 필터)와는 별개의 신규 상태다.
- **상태**: `stores/map.ts`에 `carwashType: 'all' | 'self' | 'hand' | 'auto'`(기본 `'all'`) + setter 추가. `'all'`은 unknown을 포함한 전체.
- **적용**: 필터 변경 시 bbox 재조회(서버 파라미터 `type=`) 또는 클라이언트 마커 필터 중 택1. 데이터량(전국 ~1만)·EV 패턴 정합성 고려해 클라이언트 필터를 기본안으로 하되 구현 시 성능 확인.
- **기본값 정직성**: 62%가 미기재이므로 기본 `'all'`(미확인 포함)이어야 대부분의 세차장이 보인다. 셀프 등 특정 유형 선택 시 unknown은 제외됨을 UI로 인지 가능하게 한다(예: 선택 유형만 강조, "미확인 N곳 숨김" 힌트는 선택).
- **수용 기준(AC)**:
  - AC-3.1 (**필터 노출 조건**): 유형 필터 UI는 세차장 레이어에서만 보이고, gas/ev 레이어에서는 보이지 않는다.
  - AC-3.2 (**셀프 필터**): '셀프' 선택 시 지도에 wash_type=`self`인 마커만 남고, hand/auto/unknown 마커는 사라진다. 재선택/전체로 되돌리면 복원된다.
  - AC-3.3 (**전체 기본**): 레이어 최초 진입 시 필터 기본값은 '전체'이며, unknown 유형 세차장도 지도에 표시된다.
  - AC-3.4 (**미확인 정직**): '전체'에서 unknown 세차장은 표시되지만 팝업 유형은 "유형 미확인"으로 나타난다(임의로 셀프/자동으로 채워 넣지 않는다).
  - AC-3.5 (**Mock 동작**): Mock 모드에서도 유형 필터가 동작해 mock 마커가 유형별로 걸러진다(크래시 없음).

- `MapLayer` 'carwash' + FilterBar 진입 칩 + 세차장 마커 + `CarwashPopup` + 유형 필터(셀프/손세차/자동/전체).
- 유형 미확인·정보 노후 정직 표기, 출처 표기, 대표자명 제외.

### 제외(Out) — 후속 사이클/BACKLOG 이관
- **부설 세차 중복 병합**: 독립만 임포트하지만 '주유소' 오기재 행이 남을 수 있음 → 상호·좌표 근접(≈50m) 중복 판정은 v2(research §6-6). *이유*: v1은 부설 업종 문자열 제외로 충분히 방어되고, 정밀 병합은 좌표 품질 실측 후.
- **크라우드소싱 보정**(유형 제보/폐업 신고 UI): research §5 2안 — 출시 후 unknown 비율·품질 실측 뒤 결정. *이유*: 별도 rate-limit/모더레이션 인프라가 필요해 한 사이클 규모 초과.
- **시도(sido) 매핑**: 2026 행정구역 개편 명칭 불일치 → bbox 조회만 쓰는 v1은 매핑 불필요(research §6-4). 시도별 목록/`/regions` 허브 노출은 후속. *이유*: v1 지도 레이어는 좌표만으로 동작.
- **폐업 신고/영업상태 반영**: 원천에 폐업 컬럼 없음 → v1은 "정보가 오래될 수 있음" 고지 + 데이터기준일자 노후 행 정책 검토까지만. 능동적 폐업 처리는 후속(research §6-1).
- **노후 행 하한 컷 정책 확정**: `data_base_date` 하한 필터의 구체 임계값(예: 2010년 이전 제외)은 데이터 분포 실측 후 결정 → v1은 컬럼만 적재하고 표기/미표기 정책은 열어둠. *이유*: 임계값을 근거 없이 정하면 유효 데이터 손실.
- **상세 페이지(`/carwash/[id]`)**: v1은 팝업까지. 이력/리뷰 등 상세는 후속. *이유*: 세차장은 가격 이력이 없어 상세의 부가가치가 낮음, 규모 관리.
- **카카오 실시간 검색 보조**(research §5 3안): 약관상 저장 없이만 가능하고 DB 레이어와 가치 중복 → 비채택 기록.

## 성공 지표 (사이클 후 확인 가능한 것)

- **커버리지**: `carwash_places` 적재 행 수가 1만 곳 내외(부설 제외 후 독립 세차장, research §3.1 '세차' 업종 10,838행 기준)이고, 좌표 범위 밖 행 0건.
- **데이터 품질 가시화**: wash_type 분포(self/hand/auto/unknown)를 로그/응답으로 확인 가능. unknown 비율을 실측해 FR-3 후속(크라우드소싱) 판단 근거로 삼는다.
- **기능 동작**: 세차장 레이어 전환·마커·팝업·유형 필터가 QA 시나리오(AC 전항)에서 통과.
- **안정성**: sync 실패를 유도해도 기존 데이터가 유지됨(전체삭제 0). Mock 모드에서 크래시 0.
- **유입(후행)**: "OO동 셀프세차장" 롱테일 검색 유입 관찰(출시 후 수 주, `/regions` 허브 전례 커밋 `e824f69` 참고 — v1은 지도만이라 유입은 후속 지표).

## SRS 반영 제안 (제안만 — 직접 수정 금지)

1. **§1.2 데이터 출처**: 오피넷 외에 "행정안전부 전국세차장표준데이터(무료·이용허락 제한 없음)"를 부차 데이터 출처로 추가. 화면에 출처 표기 원칙을 세차장 레이어에도 명시.
2. **§3.1 지도 기반 표시**: FR-1.3에 유종/브랜드/부설세차 필터가 정의돼 있음. 신규 레이어 개념을 반영해 "레이어(주유소/EV/세차장) 전환" 항목을 FR-1.x로 신설 제안(현재 EV 레이어도 SRS 미기재 상태로 보이므로 EV와 함께 문서화).
3. **§4 데이터 모델**: `carwash_places`(및 기존 `ev_chargers`)를 데이터 모델 목록에 추가.
4. **§5 API 계약 표**: `GET /api/carwash/bbox`(공개·rate limit), `POST /api/internal/sync-carwash`(CRON_SECRET) 행 추가.
5. **용어/UX 주의**: '세차'(주유소 부설 필터)와 '세차장'(독립 세차장 레이어)의 구분을 §1.3 용어 또는 §3에 명문화(사용자·개발자 혼동 방지). 기존 부설 칩 라벨을 "주유+세차" 등으로 재명명하는 안을 함께 검토.

## 미해결/리스크

1. **영업상태(폐업) 부재**: 원천에 폐업 컬럼이 없고 데이터기준일자가 1990년대인 노후 행 존재(research §6-1). → v1 대응: `data_base_date` 적재 + "정보가 오래될 수 있음" 정직 고지(AC-2.6). 노후 행 하한 컷 임계값은 분포 실측 후(Out). 소관 문의처: 기후에너지환경부 수질수생태과 044-201-7067.
2. **다운로드 엔드포인트 비공식성**: `file.localdata.go.kr`는 포털 폐쇄 후 남은 파일서버, Referer 없이 403(research §6-2). URL 변경/중단 리스크. → sync 실패 안전(전체삭제 금지, 마지막 스냅샷 유지, AC-1.6) + 실패 시 응답 에러 기록. 운영 알림은 후속.
3. **세차유형 62% 미기재**: 정규화 후에도 unknown 다수 예상. → "유형 미확인" 정직 표기(AC-2.5) + 필터 기본 '전체'(AC-3.3). 정확한 unknown 비율은 구현 후 실측(성공 지표).
4. **좌표 이상치 미검증**: 채움률만 확인, 0,0/뒤바뀜 등은 미검증(research §6-5). → 한반도 bbox 가드로 방어(AC-1.5). 주소-좌표 불일치는 잔존 가능(허용, 후속 모니터링).
5. **유형 필터 서버 vs 클라이언트**: 구현 시 성능/캐시 정합성 확인 필요(FR-3). 클라이언트 필터가 기본안이나 마커 상한과의 상호작용 주의.
6. **CSV 파싱 견고성**: cp949 디코딩·자유입력 필드(세차유형)·따옴표 이스케이프 등 실데이터 파싱 엣지케이스. → EV `toRow` 방어적 파싱 패턴 준용, 파싱 실패 행은 skip 카운트로 집계.
