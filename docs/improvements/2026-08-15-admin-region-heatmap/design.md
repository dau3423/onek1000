> 작성: 2026-08-15 디자인 담당 · 근거: 같은 폴더 `plan.md`(FR-3, Mock 전략) + `research.md`
> 대상 화면: `/admin` (라이트 테마 고정 `colorScheme:'light'` — **다크모드 대응 없음, `dark:` 클래스 금지**)
> 렌더 방식: **서버 컴포넌트**(카카오 SDK·클라이언트 JS·상태 없음. 순수 SVG+HTML)

## 확정 정책 (디자인에 그대로 반영, 변경 불가)

- 개인 핀·좌표성 표시 **절대 금지** — 시도 단위 집계 색 농도와 수치만 그린다.
- 외부 시도 경계 GeoJSON **사용 금지** — 아래 "타일 좌표 배치표"대로 직접 저작한 스키매틱 타일 지도.
- 실제 지도 윤곽 재현이 목적이 아니다. **"어느 지역이 진한가"의 가독성**이 목적.

## 화면 흐름

1. 운영자가 `/admin` 접속(기존 ADMIN_EMAILS 게이트 — 비관리자는 `notFound()`, 신규 섹션도 함께 차단됨).
2. 통계 카드 그리드 아래로 스크롤 → **"지역별 접속 (최근 7일)"** 섹션이 보인다.
3. 지도에서 색이 진한 시도를 한눈에 파악 → 옆(모바일은 아래)의 표에서 정확한 방문수·비율 확인.
4. '미상' 블록·행으로 GeoIP 실패분 비중을 확인 → 통계 신뢰도를 스스로 판단.
5. hint 문구로 한계(통신사 IP 수도권 편중)를 상기하고, attribution으로 EULA 준수.
6. 인터랙션 없음(클릭·호버 동작 없음 — 서버 렌더 정적 화면). 데스크톱 호버 시 SVG `<title>`
   네이티브 툴팁으로 "시도명 방문수"만 보이면 충분.

## 스키매틱 SVG 타일 지도 레이아웃

### 타일 좌표 배치표 (확정 — 이대로 구현)

5열(col 0–4) × 6행(row 0–5) 그리드. 한반도 상대 위치 근사. `·`는 빈 칸(렌더 안 함).

| row \ col | 0        | 1        | 2        | 3        | 4        |
|-----------|----------|----------|----------|----------|----------|
| **0**     | ·        | 서울 `01` | ·        | 강원 `03` | ·        |
| **1**     | 인천 `15` | 경기 `02` | 충북 `04` | ·        | ·        |
| **2**     | ·        | 충남 `05` | 세종 `19` | 경북 `08` | ·        |
| **3**     | ·        | 전북 `06` | 대전 `17` | 대구 `14` | 울산 `18` |
| **4**     | 광주 `16` | 전남 `07` | 경남 `09` | ·        | 부산 `10` |
| **5**     | 제주 `11`†| ·        | ·        | ·        | 미상 ‡    |

- † **제주는 row 5에 y축 +16px 추가 오프셋**으로 본토와 분리(좌하단 섬 표현).
- ‡ **미상은 지리 타일이 아니다** — 같은 row 5 우하단(col 4, 제주와 동일 y 오프셋)에
  대시 보더 블록으로 그린다(아래 "'미상' 블록" 참조).
- 배치 근거: 인천-서울-경기 수도권 클러스터(좌상), 강원 우상, 충남-세종-대전-충북 중부,
  경북-대구-울산-부산 우측 동해안 축, 전북-광주-전남 좌하, 경남 중남부, 제주 분리.
  17개 코드는 `types/station.ts:45-54`의 `SidoCode` 전체와 1:1 — 누락 없음(구현 시
  `Record<SidoCode, {row, col}>` 타입으로 선언해 타입체크로 17개 강제).

### 좌표 계산·치수 (SVG 사용자 단위)

- 상수: `TILE = 64`, `GAP = 8`, `PAD = 8`, `JEJU_OFFSET = 16`(row 5 전용 추가 y).
- `x = PAD + col * (TILE + GAP)` → col 0~4 = **8, 80, 152, 224, 296**
- `y = PAD + row * (TILE + GAP)` → row 0~4 = **8, 80, 152, 224, 296**, row 5 = `8 + 5*72 + 16` = **384**
- **`viewBox="0 0 368 456"`** (너비 `8+5*64+4*8+8=368`, 높이 `384+64+8=456`).
  `width`/`height` 속성은 주지 않고 `className="h-auto w-full"` — 반응형 축소.
- 타일: `<rect rx="10" width="64" height="64">` — 카드류의 둥근 모서리 톤과 일치.
  기본 stroke 없음(GAP 8px가 경계 역할). 단 0/무데이터 타일(#F3F4F6)은 흰 카드 배경과
  구분 위해 `stroke="#E5E7EB" strokeWidth="1"`.
- 타일 내부 라벨(둘 다 `textAnchor="middle"`, `x = tileX + 32`):
  - 시도명: `y = tileY + 28`, `fontSize 13`, `fontWeight 700` — `SIDO_NAME[code]` 그대로(이미 2글자 축약형).
  - 방문수: `y = tileY + 46`, `fontSize 11`, `fontWeight 500`, 천단위 콤마(`toLocaleString('ko-KR')`).
  - 글자색은 단계별 지정색(아래 색 스케일 표) — SVG라 Tailwind 대신 hex 속성 직접 지정.
- 각 타일 그룹에 `<title>{시도명} {방문수}명</title>` — 데스크톱 네이티브 툴팁 + 접근성 텍스트.
- SVG 루트: `role="img" aria-label="시도별 최근 7일 방문 단계구분도"`.
- **핀·마커·좌표점·경계선 세부 묘사 일절 없음** — rect 17개 + 텍스트 + 미상 블록이 전부.

- 1↔2단계(blue-100→300), 2↔3단계(blue-300→600)의 도약이 커 보이지만 **의도된 선택**:
  4단계 분류에서는 인접 단계가 한눈에 구분되는 것이 등간격 그라데이션보다 중요하다.

## 수치 표

- 마크업·클래스는 `app/admin/daily-top10/DailyTop10Client.tsx:66-106` `Top10Table` 관례를 따른다
  (`<table className="w-full text-sm">`, thead `border-b border-gray-200 text-left text-xs text-gray-500`,
  tbody 행 `border-b border-gray-100 last:border-0`).
- **컬럼 4개** (343px 뷰포트에서 무스크롤):

| 컬럼 | th 클래스 방향 | td 클래스 방향 |
|------|---------------|---------------|
| 순위 | `w-10 py-2 text-center font-medium` | `py-1.5 text-center text-gray-500 tabular-nums` |
| 시도 | `py-2 font-medium` | `py-1.5 font-semibold text-gray-900` |
| 방문수 | `py-2 text-right font-medium` | `py-1.5 text-right font-bold tabular-nums text-gray-900` |
| 비율 | `w-14 py-2 text-right font-medium` | `py-1.5 text-right tabular-nums text-gray-500` |

- **정렬**: 방문수 내림차순. **17개 시도 전부 항상 행으로 노출**(방문 0인 시도도 `0` / `0.0%`로 —
  숨기면 "데이터가 없는 건지 누락인지" 판단 불가). 관리자 1인 화면이므로 18행 세로 길이는 허용
  (접기/페이지네이션 불요).
- **비율**: 분모 = 미상 포함 기간 전체 방문수. 소수 1자리(`(v/total*100).toFixed(1)%`).
- 행 밀도는 `py-1.5`로 TOP10 표보다 약간 촘촘하게(18행 수직 부담 완화). 데스크톱 2열 배치에서
  지도 높이와 대략 맞는다.
- `<caption className="sr-only">시도별 최근 7일 방문수와 비율</caption>` 추가(스크린리더용).

### '미상' 행 (표)

- 17개 시도 행 **아래에 고정**(정렬에 섞지 않는다 — 지리 항목과 성격이 다름).
- 스타일로 구분: `<tr className="border-t border-gray-200 bg-gray-50">`, 순위 셀 `—`,
  시도 셀 `미상 <span className="text-[10px] text-gray-400">(지역 추정 실패)</span>`,

- 미상 0건이어도 행은 항상 렌더(`0` / `0.0%`) — "정직 노출" 원칙.

## 미해결/리스크

1. **타일 배치의 지리 정합 한계**: 5×6 그리드 근사라 광주(전남 좌측 배치)·울산(대구 우측) 등이
   실지리와 미세하게 다르다. 목적(농도 비교)상 허용— 운영자 피드백 후 배치표만 바꾸면 되는 구조
   (`TILE_GRID` 상수 수정만으로 조정 가능).
2. **분위 임계값 겹침**: 실데이터 초기(값이 0~2개뿐)에는 Q1=Q2=Q3가 되어 단계가 2~3개로 보일 수
   있다. 범례가 실제 임계값을 그대로 보여주므로 오독은 없지만, 시각적으로 밋밋할 수 있음 — 허용.
3. **미상 비중이 클 때의 인상**: GeoIP 도입 전/실패 시 지도가 전부 회색+미상만 커진다. 이는 의도된
   정직 노출이나, 운영자가 "고장"으로 오인할 수 있어 폴백 문구·hint로 보완했다. '미상 비율 전용
   카드'는 plan에서 Out(BACKLOG).
4. **표 18행의 세로 길이(모바일)**: 375px에서 섹션이 길어진다. 관리자 1인 화면이라 접기 없이
   수용하기로 판단 — 불편 피드백 시 v2에서 "상위 8 + 더보기" 검토.
5. **SVG `<title>` 툴팁의 모바일 미동작**: 보완 수단(표)이 있어 수용. 탭 인터랙션 추가는 클라이언트
   JS가 필요해 서버 컴포넌트 제약과 충돌 — 하지 않는다.
6. plan FR-1(스키마)·FR-2(수집 파이프라인)·privacy 문구는 화면이 없는 요구사항으로 이 명세 범위
   밖(구현 명세는 plan 참조). FR-3의 화면 요구는 본 문서에 전부 반영됨.
