### 2. "데이터로 리텐션을 볼 수 있는가" 평가

**현재는 사실상 불가.**
- 계측된 이벤트는 `landing_view → signin_view → oauth_click/email_submit → auth_success` 가입 퍼널뿐(`app/api/event/route.ts:28-35`). 핵심 가치 행동(지도 탐색, 주유소 상세 진입, 길찾기 클릭, 예측 카드 열람, 경로 최저가 사용, 주유 기록 저장)은 **아무것도 계측되지 않는다**.
- 리텐션 지표는 `returning_user_count`(로그인 사용자 중 다른 날짜 2회+ 방문한 누적 인원) 단 하나 — 기간·코호트 개념이 없어 "이번 주 개선이 리텐션을 올렸는가"에 답할 수 없다(`lib/db/stats.ts:84-95`).
- 유입 채널: `page_visits`/`funnel_events`에 **referrer/UTM 컬럼이 없다**(`supabase/migrations/0033`, `lib/db/stats.ts:23-61`). "SEO 랜딩이 유입을 만들고 있는가"를 자체 데이터로 검증 불가. GA4 page_view가 있어 콘솔에서 채널 구분은 가능하나(신뢰수준: 중 — 설정·수집 여부 미확인) 관리자 대시보드와 단절되어 있다.
- 비로그인 사용자가 대다수일 것으로 추정되는데(가설), 디바이스 기준 D1/D7 재방문율 산출 쿼리가 없다. 데이터 원천(`page_visits`의 `visit_date × device_id`)은 이미 쌓이고 있어 **RPC 추가만으로 소급 산출 가능**하다.

## 문제/기회 (사용자 관점)

1. **들어올 문이 좁다.** 웹 서비스라 앱스토어 존재감이 없고(TWA는 README `정식 출시 단계` 미착수 항목), 검색 유입은 구글향 SEO만 정비됨. 한국 검색은 측정기관에 따라 네이버 44~81%로 여전히 네이버 비중이 크고, 네이버는 독립 웹사이트(웹문서)보다 블로그·카페·플레이스가 노출을 지배한다 — 네이버 서치어드바이저 등록만으로 노출이 보장되지 않는다(아래 외부 조사). 즉 **네이버 세계에는 사실상 진입 못한 상태**(가설, 신뢰수준 중).
2. **바이럴 루프가 없다.** "이 주유소 싸다"를 친구에게 보내는 공유 버튼이 주유소 상세·TOP10 어디에도 없고(OG 카드는 준비돼 있는데 쓰는 버튼이 없음), 레퍼럴 보상은 전면무료 기간이라 무의미해졌다.
3. **돌아올 이유(훅)는 만들어 놨는데 배달이 안 된다.** 아침 유가 전망 푸시·주간 다이제스트·추세 배너 등 재방문 훅은 풍부하지만, (a) 푸시는 로그인+옵트인+웹푸시 구독이라는 3중 관문 뒤에 있고 비로그인은 원천 배제, (b) weekly-digest·데일리 트윗은 크론 미등록 추정으로 발송/발행 자체가 안 되는 것으로 보인다.
4. **개선의 성패를 판정할 계기판이 없다.** 위 §2. 어떤 유입·리텐션 실험을 해도 효과를 못 잰다 — 성장 정체의 원인 규명이 불가능한 구조.
5. **데이터 신뢰 이슈는 기회.** 오피넷 원천 데이터가 할인가/실판매가를 구분 못 해 실제 가격과 다른 사례가 보도됨(아래 외부 조사) — 사용자 제보/"가격 확인됨" 배지는 경쟁사(오일나우)가 이미 무기로 쓰는 차별화 포인트.

## 개선 방향 제안 (요약 2~3개)

### 제안 1 — "성장 계기판" 구축 (B1) : 최우선
- **내용**: 핵심 행동 이벤트 + referrer/UTM + D1/D7 디바이스 코호트 리텐션을 관리자 대시보드에 상설화.
- **기대 효과**: "SEO가 유입을 만드는가", "예측 카드가 재방문을 만드는가"를 처음으로 데이터로 답할 수 있게 됨. 이후 모든 성장 실험의 전제 조건.
- **예상 비용**: 중(마이그레이션 1개 + 이벤트 훅 7~10곳 + RPC 2개 + 대시보드 카드). 반나절~1일. 기존 `funnel_events`/`page_visits` 패턴 재사용이라 리스크 낮음.

### 제안 2 — "만들어 놓고 안 켠 것" 가동 (A1+B2) : 최저비용
- **내용**: `post-daily-tweet`·`weekly-digest` Cloud Scheduler 등록(+X env), `docs/06` §7에 잡 2개 추가 문서화. 병행으로 네이버 블로그 채널 개설·주 2~3회 발행(A2, 운영 제안).
- **기대 효과**: 매일 자동 콘텐츠 발행(유입) + 주 1회 푸시 다이제스트(재방문)가 0에 가까운 개발 비용으로 켜짐.
- **예상 비용**: 소(설정/문서 + 운영 루틴). 단, 실가동 여부는 프로덕션 스케줄러 확인 필요(미해결 1).

### 제안 3 — 공유 루프 + 푸시 관문 완화 (A4+B3)
- **내용**: 주유소 상세/TOP10 공유 버튼 + 주유소별 동적 OG 카드, 비로그인 푸시 옵트인 개방.
- **기대 효과**: DAU 150의 입소문 전파 경로 신설(카톡 공유가 한국 웹 유입의 실질 채널), 비로그인 다수를 재방문 가능 모수로 전환.
- **예상 비용**: 중(공유 버튼·OG 라우트는 소, 푸시 게이트 완화는 구독 API·발송 대상 쿼리 수정 필요).

## 미해결/리스크

1. **프로덕션 크론 실태 미확인**: `post-daily-tweet`/`weekly-digest`가 정말 미가동인지는 gcloud 콘솔(Cloud Scheduler 잡 목록)을 봐야 확정된다. 레포 근거(vercel.json·docs/06 부재)만으로 "미가동 추정" 판정.
2. **유입 채널 실데이터 부재**: GA4 콘솔·서치콘솔 실적을 열람하지 못해, 현 DAU 150의 출처(직접/검색/소셜)를 모른다. 제안 1(계측)이 선행돼야 나머지 레버의 효과 검증이 가능하다.
3. **오피넷 앱 리뷰 원문 수집 실패**(App Store 429) — 경쟁 앱 불만 기반 차별화 근거는 간접 출처(보도·커뮤니티)에 의존, 신뢰수준 중.
4. **X API 무료 티어 발행 한도**: 자동발행 시 월 게시 한도·정책 변경 리스크(외부 확인 필요).
5. **BETA_FREE 종료 시점 미정**: 레퍼럴 보상·푸시 게이트 설계가 전면무료 플래그에 얽혀 있어(`lib/flags.ts`), 유료 전환 시점 계획과 함께 결정해야 한다.
6. **오피넷 상업적 이용 협의 상태 미확인**(SRS §8) — 유입 확대·수익화 가속 전 법적 전제.
7. **주유로또 등 경품 이벤트**: 경품 비용·경품고지 의무(전자상거래·경품 관련 규정) 검토 필요 — 운영 리스크.
