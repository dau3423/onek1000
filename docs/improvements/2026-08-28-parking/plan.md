# 기획: 주차장 — "지금 여기서 제일 빨리 세울 수 있는 곳"

> 2026-08-28. 코드 수정 없음. 근거(파일 경로 / 실측 / URL)를 달았고, 확인하지 못한 것은 "미확인"으로 표시했다.

---

## 0. 한 줄

> **"주차장이 어디 있나"가 아니라 "지금 내 위치에서 몇 분에 세울 수 있나"를 답한다.**

지도에 주차장 핀을 뿌리는 건 카카오맵·네이버지도·모두의주차장이 이미 한다.
우리가 다르게 할 수 있는 건 **현위치 기준으로 실제 도로 소요시간을 재서 줄 세우는 것**이다.

---

## 1. 기존 서비스의 빈틈

| 빈틈 | 우리 답 |
|---|---|
| **만차를 아무도 모른다** — 전국 통합 실시간 잔여면수가 없다. 서울시는 실시간 컬럼을 아예 삭제했고 "추후 제공예정 없음" | 모른다는 걸 숨기지 않는다. 대신 **주차구획수**를 그대로 보여준다(큰 곳일수록 자리가 있을 확률이 높다는 건 사용자가 스스로 판단할 수 있는 사실이다) |
| **내 위치에서 주변 주차장 보기가 불편** — 지도에서 눈으로 찾거나, 목록이 있어도 직선거리 기준 | **도로 기준 도착 시간순 목록.** 직선 300m라도 일방통행으로 돌아가면 5분인 곳이 있다 |
| **"동선이 편한가"를 안 알려줌** | 도착 시간 + 요금 + 규모를 한 줄에 나란히 |

**핵심 통찰**: 직선거리와 실제 도착시간은 도심에서 크게 어긋난다. 그 차이가 우리 차별점이다.

---

## 2. 결정적 발견 — 호출 1회로 30곳 소요시간

카카오모빌리티 **다중 목적지 길찾기**:

```
POST https://apis-navi.kakaomobility.com/v1/destinations/directions
한 출발지 → 최대 30개 목적지, 목적지별 duration / distance 반환
```
출처: [다중 목적지 길찾기 가이드](https://developers.kakaomobility.com/guide/navi-api/destinations)

이게 없었다면 후보마다 길찾기를 1회씩 호출해야 해서(30곳=30콜) 쿼터상 불가능했다.
**조회 1회 = API 1콜**이면 성립한다. 이 API의 존재가 이 기획의 전제다.

이미 `lib/route/directions.ts` 가 같은 호스트(`apis-navi.kakaomobility.com`)를 같은 키로 쓰고 있다.

## 3. 재사용할 것 (구현 비용이 낮은 이유)

- **데이터 적재**: `전국주차장정보표준데이터` 는 `tn_pubr_prkplce_info_api` — 우리가 이미 쓰는
  `tn_pubr_*` 표준데이터 계열이다. 키 없이 확인한 결과 엔드포인트 존재를 확인했다
  (`SERVICE_KEY_IS_NOT_REGISTERED_ERROR` = 있음. 참고로 `tn_pubr_public_prkplce_info_api` 는
  `NO_OPENAPI_SERVICE_ERROR` = 없음).
  → 공용 클라이언트 `lib/dataGoKr/standardApi.ts` 를 렌터카·검사소처럼 그대로 재사용.
- **반경 조회**: `st_dwithin` 기반 RPC 패턴이 이미 있다(`supabase/migrations/0005_interest_regions.sql:53`).
- **내 주변 UX**: 반경 API + Redis 캐시(`geoQuantize`) + 시트 "내 주변" 탭이 이미 있다
  (`app/api/stations/radius/route.ts`, `components/ui/BottomSheet.tsx`).
- **레이어 파이프라인**: 세차장·정비소·렌터카에서 확립된 sync → 테이블 → bbox RPC → 마커 → 시트.

표준데이터 필드도 필요한 게 다 있다: 주차장명·소재지주소·**위도/경도**·**주차구획수**·주차장구분(공영/민영)·
주차장유형(노상/노외/부설)·운영요일·평일/토요일/공휴일 운영시각·**주차기본시간/기본요금**·
추가단위시간/요금·1일주차권요금·월정기권요금·결제방법·전화번호·장애인전용구역보유여부.

## 4. 화면 설계

### 4-1. 기본 모드 — "지금 여기" (목적지 없음)

사용자가 주차장 레이어를 켜면, **현위치 반경 후보를 도착 시간순으로** 보여준다.

```
┌──────────────────────────────────────┐
│ 내 주변 주차장 · 도착 빠른 순         │
├──────────────────────────────────────┤
│ 시청역 공영주차장            차로 3분 │
│ 320면 · 30분 1,000원 · 공영          │
├──────────────────────────────────────┤
│ 무교동 노외주차장            차로 4분 │
│ 88면 · 30분 1,500원 · 공영           │
├──────────────────────────────────────┤
│ 롯데 부설주차장              차로 7분 │
│ 540면 · 10분 1,000원 · 민영          │
└──────────────────────────────────────┘
```

**한 줄에 판단 재료를 다 넣는다**: 도착 시간 / 규모 / 요금 / 공영·민영.
점수를 숨기고 "추천"이라고만 하지 않는다 — 세차 지수·주유 타이밍에서 쓰는 톤과 같게,
**근거를 보여주고 판단은 사용자가** 한다.

### 4-2. 정렬 옵션

기본은 **빠른 순**. 그 외 **싼 순**, **큰 곳 순**(만차 회피).
가중치를 임의로 섞어 하나를 "최적"이라 단정하지 않는다 — 사람마다 급한 게 다르다.

### 4-3. 가벼운 추천 한 줄 (설명 가능한 규칙만)

상위 후보들의 도착 시간 차이가 작을 때만 한 줄 덧붙인다:

> 💡 1분 더 가면 **220면 더 큰 곳**이 있어요 (시청역 공영)

규칙이 한 문장으로 설명되는 것만 쓴다. 블랙박스 점수는 만들지 않는다.

### 4-4. 후속 — 목적지 모드

경로 모드에서 목적지가 있으면 **목적지 주변** 주차장 + **주차장→목적지 도보 시간**을 더한다.
카카오 도보 길찾기가 별도로 있다(미확인: 활용신청 필요 여부). 1단계 범위 밖.

## 5. 만차를 다루는 원칙

**모른다는 걸 정직하게 다룬다.** 이 기획에서 가장 조심할 부분이다.

- ❌ "여유 있음" / "자리 있을 거예요" — 우리는 모른다. 추정을 단정으로 쓰면 신뢰를 잃는다.
- ✅ **"320면"** — 사실만 쓴다. 큰 곳일수록 확률이 높다는 판단은 사용자가 한다.
- ✅ 실시간 정보가 있는 지자체(대구 등)는 **그 지역만** 잔여면수를 덧붙인다. 없는 곳에 빈칸을
  두는 게 틀린 값을 채우는 것보다 낫다(`오매칭 0 원칙`과 같은 태도).

## 6. 단계

| 단계 | 내용 | 선행 |
|---|---|---|
| **1** | 데이터 적재 — `parking_lots` 테이블 + `sync-parking` 크론 + bbox/radius RPC | data.go.kr 활용신청(사용자) |
| **2** | 지도 레이어 + 시트 목록(직선거리순) — 기존 레이어 패턴 그대로 | 1 |
| **3** | **다중 목적지 API로 도착 시간순 정렬** ← 차별점 | 2, 쿼터 확인 |
| **4** | 정렬 옵션 + 추천 한 줄 | 3 |
| — | 목적지 모드(도보 시간) | 후속 |

**3단계가 이 기획의 전부다.** 1~2단계만 하면 남들과 같은 주차장 지도가 된다.
3단계까지 못 갈 상황이면 시작하지 않는 편이 낫다.

## 7. 필터바 자리 문제

레이어가 이미 5개고(주유소·EV·세차장·정비소·렌터카) 320px에서 넘침을 방금 고쳤다
(`components/ui/FilterBar.tsx`). 6번째는 `+N` 뒤(`+3`)로 밀린다.

- 오버플로 구조(`SLOT_VISIBILITY` + `+N` 메뉴)가 이미 있어 **깨지지는 않는다**.
- 다만 발견성이 떨어진다 → 기존 NEW 점(`onek_seen_layers`) 메커니즘을 그대로 태운다.
- **판단 근거를 곧 얻는다**: `layer_select` 계측을 2026-08-26 에 넣었다. 며칠 뒤
  `from→to` 분포를 보면 `+N` 뒤 레이어(정비소·렌터카)가 실제로 발견되는지 알 수 있다.
  거의 안 쓰인다면 6번째 레이어가 아니라 **다른 진입점**(홈 카드 등)을 검토해야 한다.

## 8. 미확인 사항 (진행 전 확인)

1. **주차장 표준데이터 실제 규모·품질** — 행수, 좌표 충전율, **요금 필드 결측률**.
   세차장 때 `세차유형` 62% 결측 전례가 있다. 활용신청 후 1회 호출로 확정된다.
2. **다중 목적지 길찾기 활용 조건** — 별도 신청 여부, 일일 쿼터, 요금.
   기존 `v1/directions` 와 같은 키로 되는지도 확인 필요.
3. **경로/소요시간 결과 저장 가능 여부** — 카카오 약관은 실시간 호출 기반 사용만 허용한다
   (`lib/geocode/reverse.ts` 주석 참고). 저장 불가면 매 조회 호출이라 2번과 직결된다.
4. **갱신 주기** — 표준데이터는 반기~월 단위. 폐업·요금 변경 반영이 느리다.
   제보 기능(`place_corrections`)을 주차장에도 열어두는 것을 검토.
