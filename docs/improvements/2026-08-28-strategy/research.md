### B. 주차장 / 교통정보 Go·No-Go

- **교통정보 §1단계(경로 소요시간 노출)는 즉시 Go.** 버그 수준 누락이 코드로 확정됐다: `fetchRoadRoute` 가 `{path, distance, duration}` 을 반환하는데 `app/api/route-cheapest/route.ts` 의 응답 4곳(`:94, :107, :121` 및 직선 폴백)이 전부 `{stations, buffer, product, path, usedRoad}` 만 실어 보낸다. **이미 돈 주고 받은 값을 버리고 있다.**
- **주차장은 No-Go(지금은).** 이유는 데이터가 아니라 **문서가 스스로 세운 조건을 못 넘어서**다. `plan.md:129` 이 "3단계(다중 목적지 API 도착시간순)까지 못 갈 상황이면 시작하지 않는 편이 낫다"고 썼는데, 그 3단계의 전제(다중 목적지 API 활용신청 여부·쿼터·요금)가 `plan.md §8-2` 에서 **미확인**이다. 게다가 항구 유지비가 크다(표준데이터는 **월말 일괄 취합** — data.go.kr 안내). 25명 규모에서 6번째 레이어를 늘리는 것보다 §C의 정리가 먼저다.
- **경쟁에서 이길 근거는 "없다".** 카카오 T 주차만 제휴 주차장 약 1,700곳에 예약·결제까지 붙어 있다. 우리는 결제도 예약도 만차도 없다. 유일한 차별점(도착 시간순)은 아직 검증 안 된 API에 전부 걸려 있다.

### D. 제품 서사

**현재 앱은 한 문장으로 설명되지 않는다.** README와 SRS는 "주유소 가격 지도 + 1km 알람"이라 말하는데(README:3, SRS 1.1), 실제 앱에는 레이어 5개 · 알림 4~5종 · 차계부 · 리뷰 · 제보 · 긴급출동 · 레퍼럴 · 지역 랜딩이 붙어 있다. **SRS 최종 업데이트가 2026-05-30 이라 3개월치 기능이 명세에 없다.**
서사 후보 3개를 §4에 제시했고, **추천은 「지금 가면 진짜 이득인가 — 운전자의 돈 계산기」**다. traffic-info research §0의 각도를 제품 전체로 확장한 것으로, 유가·경로·연비·차계부가 하나의 축(원 단위 이득)으로 꿰이고, 렌터카·리뷰·레퍼럴이 자연스럽게 떨어져 나간다.

### E. 25명이라는 규모

- **기능을 더 늘리면 안 된다.** 8월에만 feat 커밋 36개 + 레이어 3개(세차장·정비소·렌터카)를 추가했는데(`git log --since=2026-08-01`), 그동안 **핵심 행동은 한 번도 측정되지 않았고**(§A-2), 회원은 60일간 6명 늘었다(PM 실측).
- **퍼널 2.2%는 "기능 부족"의 증거가 아니다.** 지도 기본 진입 레벨이 5이고(`components/map/KakaoMap.tsx:288`), 가격 라벨은 level ≤ 5에서 이미 뜬다(`:46`). 즉 **첫 화면에서 가격이 이미 보인다** — 상세를 안 열어도 답이 나온다. 이건 이탈이 아니라 만족일 수 있다(가설). 그런데 이 가설을 가를 유일한 데이터(`place_click`)가 §A-2 때문에 안 쌓인다.
- **동종 카테고리는 규모로도 돈이 안 된다.** 오일나우는 누적 250만 사용자에도 2023년 연 20억 원대 손실이고, 실제 매출은 앱이 아니라 직영 주유소 석유 판매에서 나온다(나무위키). **"유저를 모으면 광고로 번다"는 경로는 이 카테고리에서 이미 실패한 경로다.**
- 결론: **이번 사이클은 "기능 추가 0, 계측 복구 + 덜어내기 + 서사 하나"** 여야 한다.

- **근거**: 앱 내 호출부 0건. 호출되면 `fetchAvgBySido` 로 **오피넷 API를 직접 호출**한다(`app/api/avg-price/route.ts:10`) — 인증 없는 공개 GET이므로 외부에서 반복 호출하면 우리 오피넷 쿼터가 소모된다.

- **제거 시 잃는 것**: 없음(`types/station.ts` 의 `AvgPriceResponse` 타입은 다른 곳에서 쓰는지 **미확인**).

## D-3. 왜 후보 1인가

1. **남이 못 만든다.** 카카오맵은 우회이득을 계산할 이유가 없고(가격 데이터가 부가 정보), 오피넷은 지도 앱이 아니며, 오일나우는 추천 알고리즘을 블랙박스로 준다.
2. **이미 있는 자산으로 대부분 된다.** 길찾기 duration(버리는 중), `fuel_logs` 평균 연비(`FuelReport.tsx`), `rpc_stations_along_path`(0015), 예측(0026).
3. **덜어낼 것이 자동으로 정해진다.** "원 단위 이득 계산에 기여하는가"로 물으면 렌터카·레퍼럴·리뷰가 스스로 떨어진다.
4. **오피넷의 구조적 약점을 우회한다.** 오피넷 자동수집은 하루 6회만 반영되어 표시가와 현장가가 어긋난다(에너지플랫폼뉴스 보도). **가격 절대값 경쟁은 우리가 이길 수 없는 싸움**이고, "이득/손해 판단"으로 옮기면 그 약점이 덜 치명적이다.

## 미확인 사항 (진행 전 확인 필요)

1. **Upstash Redis가 프로덕션에서 켜져 있는가.** `apphosting.yaml` 에 `UPSTASH_REDIS_REST_URL/TOKEN` 선언이 없다 → `lib/cache/redis.ts:7` 기준 캐시 전체 no-op 추정. **확인**: 운영 로그에서 `redis get fail` 부재 또는 bbox 응답시간 관찰. 꺼져 있으면 이벤트 rate-limit도 무효(`app/api/event/route.ts:107`).
2. **비밀번호 재설정 메일이 실제로 나가는가.** `RESEND_API_KEY`/`RESET_FROM` 이 `apphosting.yaml` 에 없다 → 이메일 회원 4명 복구 불가 추정. **확인**: `/auth/forgot-password` 1회 실행.
3. **Cloud Scheduler 실제 잡 목록.** 문서(`docs/06`, `repair-sync/README`)에는 13개 명령이 있지만 `sync-ev`·`sync-highway`·`backfill-*` 는 어디에도 없다. `post-daily-tweet`·`weekly-digest` 가동 여부도 2026-08-14 사이클부터 계속 미확인. **확인**: `gcloud scheduler jobs list --location=asia-northeast3 --project=onek1000`.
4. **레이어별 실제 사용량.** §A-2 결함 때문에 **현재 측정 불가.** 화이트리스트 복구 후 최소 1주 필요. **그때까지 레이어 관련 결정(렌터카 제거, 주차장 추가)은 전부 근거가 없다.**
5. **`auth_gate` reason 분포** — 이건 화이트리스트에 있으므로 **지금 조회 가능**. 로그인 병목의 원인(navi인지 favorite인지 forecast인지)을 즉시 가를 수 있다.
6. **`locale_active` 로케일 분포** — 지금 조회 가능. i18n 축소 판단의 유일한 근거.
7. **기존 구독자 수(subscriptions 활성 행)** — 0이면 `billing-charge` 크론 정지 가능. PM 실측 항목에 없었다.
8. **세차장 `wash_type` unknown 실측 비율** — `sync-carwash` 응답의 `washTypeDist` 가 문서에 기록된 적 없다. 주차장 요금 결측률 판단의 참고치.
9. **`route_search` / `fuel_log_saved` 30일 건수** — 화이트리스트에 있으므로 조회 가능. 경로 기능과 차계부의 실제 사용 규모를 모르면 §D 후보 1의 전제(차계부 연비를 우회이득에 쓴다)가 흔들린다.
10. **리뷰 작성 수** — UGC 축소 판단 근거. `reviews` 행수 미확인.
11. **카카오모빌리티 다중 목적지 길찾기 활용 조건·쿼터·요금** — parking plan §8-2에서 이월된 미확인. **주차장 착수의 전제.**
12. **`AvgPriceResponse` 타입 사용처** — `/api/avg-price` 제거 시 타입까지 지울 수 있는지.
